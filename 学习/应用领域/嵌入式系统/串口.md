# 串口（UART）

> 先读：串口是嵌入式系统最简单、最常用的通信方式。它只需要两根线就能让两个设备"对话"，是调试、通信、控制的基础工具。

**关键词**：串口、UART、波特率、TX/RX、调试、通信

## 抽象类比

电脑之间的通信像打电话——需要拨号、建立连接、挂断。串口通信像对讲机——插上就能说，简单直接，虽然慢但可靠。

在嵌入式世界，串口是最基础的"沟通能力"。没有串口，嵌入式设备就像哑巴——你无法知道它在想什么，也无法告诉它该做什么。

## 什么是串口？

**一句话定义**：串口（UART，Universal Asynchronous Receiver/Transmitter）是一种**异步串行通信协议**，通过两根数据线（发送 TX 和接收 RX）实现设备间的点对点通信。

### 生活比喻

- **并行通信**：像多车道高速公路，多辆车同时跑，但需要同步协调
- **串行通信**：像单车道公路，一辆一辆走，但简单可靠
- **串口（UART）**：像对讲机——你一句我一句，虽然慢但稳定

**简单说**：串口 = 发送线（TX）+ 接收线（RX）+ 地线（GND）= 三根线搞定通信

## 串口的核心特点

### 为什么串口在嵌入式中无处不在？

| 特点 | 说明 | 类比 |
|------|------|------|
| **简单** | 只需 2-3 根线 | 像两人对话，不需要第三方 |
| **便宜** | 硬件成本极低 | 像写信，只需要纸和笔 |
| **可靠** | 抗干扰能力强 | 像面对面说话，不容易听错 |
| **通用** | 几乎所有设备都支持 | 像普通话，大家都懂 |
| **调试友好** | 可以打印日志 | 像设备的"心声" |

### 串口 vs 其他通信方式

| 通信方式 | 线数 | 速度 | 复杂度 | 典型用途 |
|---------|------|------|--------|---------|
| **UART（串口）** | 2-3 根 | 慢（115200 bps） | 简单 | 调试、简单控制 |
| **I2C** | 2 根 | 中（400 KHz） | 中等 | 传感器、EEPROM |
| **SPI** | 4 根 | 快（几十 MHz） | 中等 | Flash、显示屏 |
| **USB** | 4 根 | 很快（480 Mbps） | 复杂 | 键盘、摄像头 |
| **CAN** | 2 根（差分） | 中（1 Mbps） | 复杂 | 汽车电子 |

**类比**：串口像自行车——速度慢但简单可靠；USB 像高铁——速度快但系统复杂。

## 串口的工作原理

### 基本通信过程

```
设备 A                        设备 B
  │                            │
  │── TX（发送）──────────────►│ RX（接收）
  │◄─ RX（接收）───────────────│ TX（发送）
  │── GND（地线）─────────────│ GND（地线）
  │                            │
```

### 数据发送过程

**1. 空闲状态**：线路保持高电平（1）

**2. 起始位**：发送低电平（0），告诉对方"我要开始说话了"

**3. 数据位**：发送 8 位数据（从低位到高位）
```
例如发送 'A'（ASCII 65 = 01000001）：
发送顺序：1 → 0 → 0 → 0 → 0 → 0 → 1 → 0
         （低位先送）
```

**4. 校验位（可选）**：用于检查传输错误

**5. 停止位**：发送高电平（1），表示"我说完了"

### 生动比喻

串口传输像发电报：
- **起始位**：像"滴"一声，表示开始
- **数据位**：像摩斯电码，一个点一个划
- **停止位**：像"答"一声，表示结束
- **波特率**：像发电报的速度——太快容易听错，太慢浪费时间

## 串口的关键参数

### 必须匹配的 4 个参数

| 参数 | 说明 | 常见值 | 类比 |
|------|------|--------|------|
| **波特率（Baud Rate）** | 传输速度（每秒传输的位数） | 9600, 115200 | 像说话速度——太快听不清，太慢效率低 |
| **数据位（Data Bits）** | 每次传输的数据位数 | 8 位 | 像每次说几个字 |
| **校验位（Parity）** | 错误检测方式 | None, Even, Odd | 像 checksum，确认没听错 |
| **停止位（Stop Bits）** | 结束标志位数 | 1 位 | 像句号，表示一句话结束 |

**常用配置**：`115200-8-N-1`
- 波特率：115200
- 数据位：8
- 校验位：无（None）
- 停止位：1

**类比**：串口参数像两个人约定说话方式——必须用同样的语速、同样的语言、同样的标点，才能听懂对方。

## 设计哲学

串口的设计哲学可以浓缩为一句话：**用最简单的方式实现可靠的点对点通信**——能两根线解决的事，就不用四根线。

### 解决的核心问题

嵌入式设备需要和外部世界（电脑、传感器、其他模块）通信，但嵌入式资源有限：引脚少、内存小、成本低。复杂的通信协议（如 USB、以太网）虽然速度快，但需要大量硬件资源和复杂的软件栈，不适合简单的 MCU。串口解决的核心问题是：**如何用最少的引脚（2-3 根线）、最简单的硬件、最少的代码，实现设备间可靠的双向通信？**

### 关键设计取舍

| 取舍维度 | 选择 | 放弃 | 类比 |
| :--- | :--- | :--- | :--- |
| **简单 vs 高速** | 2-3 根线、协议极简 | Mbps 级的高速传输 | 像对讲机 vs 视频通话 |
| **异步 vs 同步** | 无需时钟线、各自计时 | 同步通信的精确时序 | 像各看各的表 vs 统一报时 |
| **点对点 vs 多机** | 一对一通信简单可靠 | 多设备共享总线 | 像两人私聊 vs 群聊 |
| **可靠 vs 高效** | 起始位/停止位/校验位保证可靠 | 纯数据传输的最高效率 | 像挂号信 vs 普通信 |
| **通用 vs 专用** | 几乎所有芯片都支持 | 针对特定场景的极致优化 | 像普通话 vs 方言 |

### 设计哲学的深层逻辑

1. **极简主义**：串口只需要 TX、RX、GND 三根线，协议只需要起始位、数据位、停止位。这种极简让它能在任何 MCU 上运行，成本几乎为零。
2. **异步通信的智慧**：串口不需要独立的时钟线，发送方和接收方各自按约定的波特率计时。这牺牲了一点精度（需要双方波特率匹配），但省了一根线，简化了硬件。
3. **调试优先**：串口是嵌入式开发中**唯一可靠的"求救通道"**——当系统启动失败、屏幕不亮、网络不通时，串口打印是你能看到系统状态的最后手段。
4. **够用就好**：115200 bps 的速度对调试日志和简单控制足够了。追求更高速度有 SPI、USB 等方案，但它们更复杂、成本更高。串口赢在"简单到不会出错"。

**核心类比**：串口像**对讲机**——虽然慢（一次说一句），但简单（两根线）、可靠（抗干扰）、通用（所有人都支持）。USB 像高铁——快但系统复杂，I2C 像会议桌——多设备共享但需要协调。在嵌入式世界，对讲机式的串口永远是最基础的"沟通能力"。

## 串口的实际用途

### 1. 调试打印（最常用）

**场景**：在代码中插入打印语句，通过串口查看程序运行状态

```c
// 示例代码
printf("系统启动中...\n");
printf("NPU 驱动加载：%s\n", status ? "成功" : "失败");
printf("当前温度：%d°C\n", temperature);
```

**在电脑上看到**：
```
系统启动中...
NPU 驱动加载：成功
当前温度：45°C
```

**类比**：串口打印像设备的"日记"——你可以通过读日记了解它在做什么、遇到什么问题。

### 2. 命令行交互

**场景**：通过串口发送命令，控制设备

```
电脑发送：led on
设备响应：LED 已打开

电脑发送：motor speed 100
设备响应：电机速度设置为 100

电脑发送：sensor read
设备响应：温度：25°C，湿度：60%
```

**类比**：像微信聊天——你发消息，设备回复，双向互动。

### 3. 模块通信

**场景**：连接各种传感器和模块

| 模块 | 用途 | 通信内容 |
|------|------|---------|
| **GPS 模块** | 获取位置信息 | 经纬度、时间、速度 |
| **蓝牙模块** | 无线通信 | 各种数据 |
| **WiFi 模块** | 网络连接 | 网络数据 |
| **电机控制器** | 控制电机 | 速度、方向、位置 |

**类比**：串口像设备的"嘴巴和耳朵"——通过它和其他模块"聊天"。

### 4. 固件烧录

**场景**：通过串口将程序烧录到芯片

```
电脑 ──串口──► 开发板
    发送固件数据
```

**优势**：
- 不需要额外的烧录器
- 简单可靠
- 适合小批量烧录

## 串口硬件连接

### 最简连接（3 根线）

```
电脑（USB 转串口）          开发板（RK3588）
   │                          │
   │── TX ───────────────────►│ RX
   │◄─ RX ────────────────────│ TX
   │── GND ──────────────────│ GND
   │                          │
```

### 关键规则

**TX 接 RX，RX 接 TX**（交叉连接）

- 设备的发送（TX）接电脑的接收（RX）
- 设备的接收（RX）接电脑的发送（TX）
- 地线（GND）必须连接，提供公共参考电平

**类比**：像两个人打电话——你的嘴巴（TX）对着对方的耳朵（RX），对方的嘴巴（TX）对着你的耳朵（RX）。

### USB 转串口模块

现代电脑没有串口，需要 USB 转串口模块：

| 芯片 | 特点 | 价格 |
|------|------|------|
| **CH340** | 国产，便宜，常用 | 几元 |
| **CP2102** | 稳定，兼容性好 | 十几元 |
| **FT232** | 专业，可靠 | 几十元 |

**类比**：USB 转串口模块像翻译官——电脑说 USB 语言，开发板说串口语言，翻译官在中间传话。

## 串口常见问题与排查

### 1. 没有输出

**症状**：打开串口，什么都看不到

**排查步骤**：
```
1. 检查接线：TX-RX 是否交叉？GND 是否连接？
2. 检查波特率：是否匹配？（常用 115200）
3. 检查程序：代码中有 printf 吗？
4. 检查驱动：USB 转串口模块驱动装了吗？
5. 检查权限：Linux 下是否有权限访问 /dev/ttyUSB0？
```

**类比**：像电话打不通——可能是号码错了、线断了、对方没开机、或者你没话费了。

### 2. 乱码

**症状**：看到的是乱字符，不是正常文本

**常见原因**：
- 波特率不匹配（最常見）
- 接线错误
- 电平不匹配（3.3V vs 5V）

**解决**：
```
1. 确认波特率一致（尝试 9600、115200 等）
2. 检查 TX-RX 是否交叉
3. 确认电平匹配（RK3588 是 3.3V）
```

### 3. 数据丢失

**症状**：打印的内容不完整，断断续续

**原因**：
- 波特率太高，超过硬件能力
- 接收缓冲区满，来不及处理
- 线缆太长或质量差

**解决**：
```
1. 降低波特率（如从 115200 降到 9600）
2. 缩短线缆长度
3. 使用质量好的线缆
```

### 4. 无法发送

**症状**：能接收数据，但不能发送

**排查**：
```
1. 检查 TX 线是否接好
2. 检查程序是否正确打开串口
3. 检查串口是否被其他程序占用
```

## 面试速答

### Q: 串口（UART）通信的基本原理是什么？
A: 串口是**异步串行通信协议**，通过 TX（发送）和 RX（接收）两根线实现点对点双向通信。发送时按位依次传输（起始位→数据位→校验位→停止位），双方按约定的波特率各自计时，无需时钟线。接线规则是 TX 接 RX、RX 接 TX、GND 共地。类比：像两人用对讲机聊天，简单但可靠。

### Q: 串口通信为什么需要匹配波特率？不匹配会怎样？
A: 串口是异步通信，没有独立时钟线，发送方和接收方必须按相同的波特率各自计时才能正确采样数据位。波特率不匹配会导致采样位置错位，接收到的数据全是乱码。常见配置是 115200-8-N-1（波特率 115200、8 数据位、无校验、1 停止位）。排查乱码问题，第一步就是检查波特率是否一致。

### Q: 串口和 I2C、SPI 有什么区别？分别在什么场景用？
A: 串口是**点对点异步**通信，2-3 根线，速度慢（~115200 bps），适合调试打印和简单控制；I2C 是**多机同步**通信，2 根线（SCL+SDA），速度中等，适合连多个传感器；SPI 是**多机同步全双工**，4 根线，速度快（几十 MHz），适合 Flash 和显示屏。选型看速度需求、设备数量和引脚预算。

### Q: 串口在嵌入式开发中为什么这么重要？
A: 因为串口是嵌入式开发中**唯一可靠的调试通道**。当系统启动失败、屏幕不亮、网络不通时，串口打印是你能看到系统状态的最后手段。没有串口，嵌入式开发就像"盲人摸象"——你完全不知道设备内部发生了什么。所以串口是嵌入式工程师的"第一把钥匙"。

### Q: 串口通信出现乱码，如何排查？
A: 按以下顺序排查：1) 检查接线——TX 和 RX 是否**交叉连接**（TX 接 RX），GND 是否共地；2) 检查波特率——发送方和接收方是否一致（最常见原因）；3) 检查电平——3.3V 和 5V 不能直连，需要电平转换；4) 检查参数——数据位、校验位、停止位是否一致。90% 的乱码问题是前两个原因。
