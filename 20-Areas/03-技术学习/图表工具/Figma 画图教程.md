## 一、介绍

### 1.1 什么是 Figma

Figma 是一款基于云的协作设计工具，用于绘制 UI/UX、图表和原型。

**特点**：
- 实时协作
- 组件库丰富
- AI 集成（MCP）
- 跨平台

**应用场景**：
- 系统架构图
- 分层架构图
- 流程图
- 状态图
- 时序图
- 团队协作文档

### 1.2 与其他工具对比

| 工具 | 优势 | 劣势 |
|------|------|------|
| Figma | 协作强、组件库丰富、AI 集成 | 需要网络 |
| draw.io | 免费、离线可用 | 协作弱 |
| Excalidraw | 手绘风格、快速 | 功能简单 |
| Mermaid | 代码生成、版本控制 | 定制性差 |

## 二、架构图绘制

### 2.1 什么是架构图

展示系统各模块之间的关系和依赖。

### 2.2 架构图模板

```
┌─────────────────────────────────────┐
│         Application Layer           │
│  ┌──────────┐    ┌──────────┐      │
│  │  Web UI  │    │ Mobile   │      │
│  └──────────┘    └──────────┘      │
└─────────────────────────────────────┘
                ↓
┌─────────────────────────────────────┐
│        Business Logic Layer         │
│  ┌──────────┐    ┌──────────┐      │
│  │ Service A│    │ Service B│      │
│  └──────────┘    └──────────┘      │
└─────────────────────────────────────┘
                ↓
┌─────────────────────────────────────┐
│           Data Layer                │
│  ┌──────────┐    ┌──────────┐      │
│  │ Database │    │  Cache   │      │
│  └──────────┘    └──────────┘      │
└─────────────────────────────────────┘
```

### 2.3 Figma 绘制步骤

#### 步骤 1：创建背景容器

1. 按 `R` 绘制大矩形（背景层）
2. 设置填充颜色（浅灰色 #F5F5F5）
3. 添加文字标签（Layer Name）

#### 步骤 2：添加模块

1. 按 `R` 绘制小矩形（模块）
2. 设置填充颜色（蓝色 #E3F2FD）
3. 添加模块名称
4. 按 `Ctrl+D` 复制多个模块

#### 步骤 3：连接模块

1. 按 `L` 绘制线条
2. 设置箭头样式（属性面板 → Line arrow）
3. 调整线条粗细（2-3px）

#### 步骤 4：添加标签

1. 按 `T` 添加文字
2. 说明关系（如 "调用"、"依赖"）

### 2.4 配色方案

| 层级 | 颜色 | 用途 |
|------|------|------|
| 表示层 | #E3F2FD（浅蓝） | UI、API Gateway |
| 业务层 | #E8F5E9（浅绿） | 服务、逻辑 |
| 数据层 | #FFF3E0（浅橙） | 数据库、缓存 |
| 外部系统 | #F3E5F5（浅紫） | 第三方服务 |

## 三、分层图绘制

### 3.1 什么是分层图

展示系统的层次结构和每层的职责。

### 3.2 分层图模板（以 StarryOS 为例）

```
┌──────────────────────────────────────┐
│        Application Layer             │
│  Tennis Robot / LeRobot Framework    │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│         Runtime Layer                │
│    ROS2 / Middleware / Scheduler     │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│          Kernel Layer                │
│  Memory / Task / IPC / Filesystem    │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│          Driver Layer                │
│   NPU / UART / USB / Camera Driver   │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│         Hardware Layer               │
│         RK3588 Board                 │
└──────────────────────────────────────┘
```

### 3.3 Figma 绘制步骤

#### 步骤 1：创建分层容器

1. 按 `R` 绘制 5 个大矩形（代表 5 层）
2. 垂直排列，间距一致
3. 每层设置不同颜色

#### 步骤 2：添加层内组件

1. 在每层内添加小矩形（组件）
2. 水平排列
3. 使用相同色系的不同深浅

#### 步骤 3：添加层间箭头

1. 按 `L` 绘制垂直箭头
2. 从上到下或从下到上
3. 标注接口名称

#### 步骤 4：添加说明

1. 每层右侧添加文字说明
2. 说明该层职责

### 3.4 设计要点

- ✅ 层与层之间清晰分隔
- ✅ 每层颜色统一但深浅不同
- ✅ 箭头标明数据流向
- ✅ 文字说明简洁明了

## 四、流程图绘制

### 4.1 什么是流程图

展示业务流程或算法执行流程。

### 4.2 流程图模板（以 UART 驱动初始化为例）

```
     ┌──────────┐
     │  Start   │
     └──────────┘
          ↓
     ┌──────────┐
     │ Clock    │
     │ Config   │
     └──────────┘
          ↓
     ┌──────────┐
     │ GPIO     │
     │ Config   │
     └──────────┘
          ↓
    ┌────────────┐
    │ UART Init  │
    │ Baud Rate  │
    └────────────┘
          ↓
    ┌──────────────┐
    │ Interrupt    │
    │ Enable?      │
    └──────────────┘
       ↓        ↓
     Yes        No
       ↓        ↓
  ┌────────┐ ┌────────┐
  │Enable  │ │  End   │
  │IRQ     │ │(Polling)│
  └────────┘ └────────┘
       ↓
  ┌──────────┐
  │   End    │
  └──────────┘
```

### 4.3 Figma 绘制步骤

#### 步骤 1：创建节点

1. **开始/结束**：按 `O` 绘制椭圆（绿色 #C8E6C9 / 红色 #FFCDD2）
2. **处理步骤**：按 `R` 绘制矩形（蓝色 #BBDEFB）
3. **判断节点**：按 `D` 绘制菱形（黄色 #FFF9C4）

#### 步骤 2：连接节点

1. 按 `L` 绘制线条
2. 属性面板设置箭头（Line arrow → Arrow）
3. Yes/No 分支标注文字

#### 步骤 3：对齐和分布

1. 选中多个节点
2. 右键 → Align horizontal centers
3. 右键 → Distribute vertical spacing

#### 步骤 4：美化

1. 统一圆角（4-8px）
2. 统一字体（14-16px）
3. 添加阴影效果

### 4.4 流程图规范

| 元素 | 形状 | 颜色 | 说明 |
|------|------|------|------|
| 开始/结束 | 椭圆 | 绿/红 | 流程起止 |
| 处理步骤 | 矩形 | 蓝 | 操作、处理 |
| 判断 | 菱形 | 黄 | 条件分支 |
| 数据 | 平行四边形 | 橙 | 输入输出 |
| 连接线 | 箭头 | 灰 | 流程方向 |

## 五、DAG 图绘制

### 5.1 什么是 DAG 图

DAG（Directed Acyclic Graph，有向无环图）展示任务依赖关系。

### 5.2 DAG 图模板（以编译流程为例）

```
         ┌──────────┐
         │ Parse    │
         └──────────┘
        ↙          ↘
  ┌──────────┐   ┌──────────┐
  │Semantic  │   │ Type     │
  │Analysis  │   │ Check    │
  └──────────┘   └──────────┘
        ↘          ↙
      ┌──────────────┐
      │Optimization  │
      └──────────────┘
            ↓
      ┌──────────┐
      │Code Gen  │
      └──────────┘
            ↓
      ┌──────────┐
      │Linking   │
      └──────────┘
```

### 5.3 Figma 绘制步骤

#### 步骤 1：创建任务节点

1. 按 `R` 绘制矩形
2. 使用相同颜色（#E3F2FD）
3. 添加任务名称

#### 步骤 2：建立依赖关系

1. 按 `L` 绘制箭头
2. 从上游任务指向下游任务
3. 确保无环（不能形成循环）

#### 步骤 3：分层布局

1. 第一层：无依赖的任务
2. 第二层：依赖第一层的任务
3. 依此类推

#### 步骤 4：标注关键路径

1. 选中关键路径的节点和箭头
2. 设置高亮颜色（红色 #FF5252）
3. 加粗线条（3-4px）

### 5.4 DAG 图设计要点

- ✅ 从左到右或从上到下布局
- ✅ 避免交叉线（如无法避免，使用跳线）
- ✅ 标注关键路径
- ✅ 节点大小统一

展示系统或对象的状态变化。

```
              ┌─────────────┐
              │    IDLE     │
              └─────────────┘
                    ↓ send()
              ┌─────────────┐
         ┌───│  SENDING    │───┐
         │   └─────────────┘   │
         │          ↓ complete  │
         │   ┌─────────────┐   │
         │   │  TX_DONE    │   │
         │   └─────────────┘   │
         │          ↓           │
         │   ┌─────────────┐   │
         └───│   IDLE      │←──┘
             └─────────────┘
                    ↓ receive()
             ┌─────────────┐
         ┌───│  RECEIVING  │───┐
         │   └─────────────┘   │
         │          ↓ complete  │
         │   ┌─────────────┐   │
         │   │  RX_DONE    │   │
         │   └─────────────┘   │
         │          ↓           │
         └───│   IDLE      │←──┘
             └─────────────┘
```

### 6.3 Figma 绘制步骤

#### 步骤 1：创建状态节点

1. 按 `R` 绘制圆角矩形（圆角 20px）
2. 设置填充颜色（#E8F5E9）
3. 添加状态名称（大写）

#### 步骤 2：添加状态转换

1. 按 `L` 绘制曲线或折线
2. 设置箭头样式
3. 在箭头上添加触发条件文字

#### 步骤 3：标注初始状态

1. 按 `O` 绘制小实心圆（黑色）
2. 箭头指向初始状态

#### 步骤 4：标注结束状态

1. 按 `O` 绘制双层圆（牛眼图标）
2. 从最终状态指向它

### 6.4 状态图规范

| 元素 | 形状 | 说明 |
|------|------|------|
| 状态 | 圆角矩形 | 系统状态 |
| 初始状态 | 实心圆 | 开始点 |
| 结束状态 | 双层圆 | 结束点 |
| 转换 | 箭头 | 状态变化 |
| 触发条件 | 文字 | 在箭头上标注 |

## 八、Figma MCP 使用

### 8.1 什么是 MCP

MCP（Model Context Protocol）是 AI 模型与工具集成的标准协议。

Figma MCP 让 AI 可以直接操作 Figma 文件。

### 8.2 Figma MCP 的优势

| 传统方式 | MCP 方式 |
|---------|---------|
| 手动绘制 | AI 生成 |
| 反复调整 | 一次生成 |
| 学习成本高 | 自然语言描述 |
| 耗时长 | 秒级生成 |

### 8.3 配置 Figma MCP

#### 步骤 1：安装 MCP 客户端

```json
// Qoder MCP 配置
{
  "mcpServers": {
    "figma": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-figma"],
      "env": {
        "FIGMA_ACCESS_TOKEN": "your_access_token"
      }
    }
  }
}
```

#### 步骤 2：获取 Figma Access Token

1. 登录 Figma
2. 设置 → Account → Create new token
3. 复制 token
4. 配置到 MCP 环境变量

#### 步骤 3：测试连接

```
AI: 请连接到 Figma MCP
系统: 已连接，可以操作 Figma 文件
```

### 8.4 使用 MCP 生成图表

#### 示例 1：生成架构图

**Prompt**：

在 Figma 中创建一个系统架构图：

- 使用蓝色系配色
- 层间用箭头连接
- 文件名称：System Architecture

**AI 操作**：
1. 创建新文件

5. 设置颜色
