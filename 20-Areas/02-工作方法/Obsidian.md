# Obsidian

> Obsidian 是基于 Markdown 的本地优先知识库工具，支持双向链接、插件扩展、图谱可视化。本文档涵盖知识库搭建方法、配置建议、插件使用和文档写作规范，帮助构建可持续积累的个人知识体系。

**关键词**：Obsidian、知识管理、双向链接、Markdown、本地优先、第二大脑

## 抽象类比

Obsidian 就像你的**第二大脑**。大脑之所以聪明，不是因为装了海量信息，而是因为神经元之间相互连接——看到一个概念能联想到另一个概念。Obsidian 的双向链接（`[[ ]]`）就是这些"神经元连接"，每条笔记都是神经元，链接就是突触。随着笔记增多，你的知识库会像大脑一样形成一张自生长的网络，越用越聪明。

---

## 为什么选 Obsidian

- **本地优先**：数据在本地，不依赖云端，安全可控
- **Markdown 格式**：通用性强，不绑定平台
- **双向链接**：`[[笔记名]]` 建立知识关联
- **插件生态**：高度可扩展
- **免费开源**：跨平台（Windows/Mac/Linux/移动端）

### 核心概念

- **笔记**：基本的 Markdown 文件
- **仓库（Vault）**：笔记的集合
- **双向链接**：`[[笔记名]]` 建立关联，支持反向链接
- **标签**：`#标签` 分类标记
- **图谱视图**：可视化笔记关系

## 知识库设计

### PARA 方法

PARA 是以行动为导向的知识组织系统，按可操作性排序：

| 层级 | 含义 | 特点 | 示例 |
| :--- | :--- | :--- | :--- |
| **P** Projects | 项目 | 有明确目标和截止日期 | "操作系统比赛"、"毕业论文" |
| **A** Areas | 领域 | 需要持续关注的责任区 | "技术学习"、"健康管理" |
| **R** Resources | 资源 | 感兴趣的主题和参考资料 | "AI 笔记"、"工具手册" |
| **A** Archives | 归档 | 已完成或不再活跃的内容 | "旧项目"、"过期文档" |

**PARA 工作流**：
```
新项目 → Projects（正在进行）
      ↓ 完成
    Archives（归档）

持续责任 → Areas（长期关注）
感兴趣主题 → Resources（参考资料）
```

**使用建议**：
1. 每周回顾：检查 Projects 是否有需要归档的
2. 新项目先放 Projects，完成后再决定移到哪里
3. Areas 不要太多（5-7 个为宜）
4. PARA 管结构，双向链接管关系

### 知识流转

```
收集 → 整理 → 内化 → 输出 → 归档
```

- **收集**：快速记录想法、摘抄、截图
- **整理**：分类、打标签、建立链接
- **内化**：重写成自己的话、添加思考
- **输出**：文章、PPT、代码、方案
- **归档**：过期内容移入 Archive

### 目录结构

```
obsidianDocument/
├── 00-Inbox/              # 收集箱（临时未整理）
├── 10-Projects/           # 进行中的项目
├── 20-Areas/              # 持续关注的领域
├── 30-Resources/          # 参考资料
├── 40-Archives/           # 已归档
├── Assets/                # 附件（图片、PDF）
├── Excalidraw/            # 绘图文件
├── Templates/             # 模板库
├── MOC.md                 # 主导航页
└── README.md              # 知识库说明
```

### 命名规范

- **文件命名**：统一中文命名，避免特殊字符 `/ \ : * ? " < > |`
- **排序前缀**：`00-`、`10-`、`20-` 等数字前缀控制排序

### MOC（内容地图）

MOC 是知识库的导航页，按主题组织相关笔记。

**创建步骤**：
1. 创建笔记，命名为 `XXX MOC.md`
2. 按主题分类，列出相关笔记链接
3. 添加简短描述
4. 定期更新

**最佳实践**：
- 一个主题一个 MOC
- 层级 2-3 层为宜
- 加简短说明，不只列链接
- 文件夹管大分类，MOC 管主题索引

## 配置建议

### 核心配置

- **附件文件夹**：`Assets/images`
- **实时预览**：开启
- **自动保存**：开启
- **主题**：Border（推荐）

### 必开核心插件

- ✅ 文件回收站、文件资源管理器、全局搜索
- ✅ 双向链接、标签面板、大纲
- ✅ 日记、模板

### 推荐社区插件

#### Templater（模板增强）

增强版模板插件，支持 JavaScript 脚本、用户输入、日期计算。

```
配置：
1. 设置 → 第三方插件 → 安装 Templater
2. Template folder location → Templates
3. 快捷键 → Ctrl+T
4. 勾选 "Trigger Templater on new file creation"
```

#### Excalidraw（绘图）

手绘风格图表，支持架构图、流程图、时序图，可嵌入笔记。

```
配置：
1. 社区插件搜索 Excalidraw
2. 设置绘图保存位置 → Excalidraw
3. 快捷键 → Alt+E 新建绘图
```

#### Dataview（数据查询）

查询和展示笔记数据，可做项目看板、任务列表。

```dataview
TABLE status, created
FROM "10-Projects"
WHERE status = "进行中"
SORT created DESC
```

### 快捷键

| 快捷键 | 功能 |
| :--- | :--- |
| `Ctrl+T` | Templater 插入模板 |
| `Alt+E` | 新建 Excalidraw 绘图 |
| `Ctrl+O` | 快速打开笔记 |
| `Ctrl+P` | 命令面板 |

## 工作流

### 日常使用

1. **收集想法** → 写入 `00-Inbox`
2. **创建日记** → `Ctrl+T` 选择日记模板
3. **整理笔记** → 从 Inbox 移到对应目录
4. **建立链接** → 使用 `[[双向链接]]`

### 每周回顾

- [ ] 清理 `00-Inbox`
- [ ] 更新 `MOC.md`
- [ ] 检查 Projects 进度
- [ ] 归档已完成项目

### 标签系统

```
#项目/比赛          # 项目分类
#技术/AI           # 技术领域
#状态/进行中        # 任务状态
#类型/概念          # 内容类型
```

## 工程型文档写作

### 核心原则

| 维度 | 传统文档 | 工程型文档 |
| :--- | :--- | :--- |
| **目标** | 记录知识 | 解决问题 |
| **结构** | 线性叙述 | 模块化拆解 |
| **语言** | 学术化 | 简洁直白 |
| **验证** | 理论推导 | 数据证明 |
| **更新** | 写完就放 | 持续迭代 |

### 写作要点

1. **问题导向**：每篇文档解决一个具体问题
2. **结构清晰**：统一模板，降低阅读成本
3. **数据驱动**：用数据、截图、日志证明
4. **可复用**：模块化内容，可组合可迁移
5. **版本管理**：Git 跟踪，可回溯

## 常见问题

- **模板不生效**：检查 Templater 插件是否启用，模板文件夹路径是否正确
- **双向链接找不到**：确保笔记名完全匹配
- **批量重命名**：Obsidian 重命名会自动更新所有链接
