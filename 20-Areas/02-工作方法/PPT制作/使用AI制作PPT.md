# AI 辅助 PPT 制作指南

> 本文档说明在提供模板 PPTX 的前提下，如何通过 AI 工具高效完成 PPT 制作。

---

## 一、核心理念

### 1.1 制作定位

PPT 制作不仅仅是"做页面"，而是：
- **结构化表达能力**的体现
- **技术价值展示**的载体
- **汇报逻辑**的可视化工具

### 1.2 内容组织原则

**正确方式：** 问题 → 挑战 → 方案 → 验证 → 成果

**错误方式：** 将过程写成流水账

### 1.3 表达核心

> 不是"学了什么"，而是"**推进了什么**"

### 1.4 工具分工

| 工具 | 职责 |
|------|------|
| ChatGPT | 思考、结构、表达、大纲、图的结构信息化 |
| Codex | 工程化生成、图表生成、操作填充 PPTX、页面修改 |
| PowerPoint | 微调、动画、演讲节奏调整 |

## 二、前期准备

### 2.1 项目梳理

明确以下要素：
- **项目定位**：所属领域与技术栈
- **当前阶段**：预研/开发/验证/优化
- **当前成果**：已完成的工程工作

建立**成果树**以体现推进内容：

```
项目名称
│
├── 已完成
│   ├── 环境搭建
│   ├── 验证工作
│   ├── 技术分析
│   └── 框架建立
│
├── 正在进行
│   ├── 适配工作
│   ├── 驱动分析
│   └── 测试设计
│
└── 未来目标
    ├── 功能集成
    ├── 性能优化
    └── 场景扩展
```

### 2.2 受众分析

提前分析评审关注点：
- 技术深度
- 工程能力
- 系统思维
- 可行性验证

### 2.3 叙事策略

PPT 不只是信息传递，更重要的是叙事结构：
- **阶段**：明确当前所处位置
- **重点**：突出核心工作
- **目标**：说明要达成的目的
- **证明**：用数据和事实支撑

## 三、工作流程

### 阶段 1：定义表达目标

**首要任务**：明确"想让评审记住什么"

**核心表达方向：**
- 架构能力
- 工程推进
- 系统理解
- 后续扩展性

**注意事项：**
- 重点不在于"项目做完了"
- 而在于建立了系统工程基础

### 阶段 2：精炼大纲结构

**工作流程：**
1. 使用 AI 作为"大纲架构师"进行多轮对话
2. 反复打磨信息结构
3. 迭代生成 outline.md

**推荐 Prompt 模板：**

```
你是一个技术答辩专家。

项目信息：
- 项目名称与技术栈
- 当前阶段与成果
- 核心技术特点

答辩时间：X 分钟展示，Y 分钟提问

目标要求：
- 强调工程推进
- 强调系统架构能力
- 避免流水账
- 彰显实事求是风格
- 多引入图的思考（DAG、架构图、流程图、分层图、模块图等）
- 每页使用树和图的思想规划内容

请输出：
1. 专业 PPT 结构
2. 每页核心目标
3. 每页适合的图表类型
4. 需要量化成果的位置
```

**迭代优化轮次：**
- **第 1 轮**：逻辑是否通顺
- **第 2 轮**：是否体现系统工程感
- **第 3 轮**：是否有量化成果
- **第 4 轮**：从评审角度审视内容质量

### 阶段 3：定义视觉风格

**目的**：将图表风格结构化，避免 AI 随机发挥

**交付物**：style.md（视觉设计规范文档）

**规范内容应包括：**
- 风格定位（技术架构风、工程风格等）
- 色彩系统（主色、辅助色、分层配色）
- 布局规范（DAG、分层架构、流水线等）
- 图像风格（极简、扁平、工程感等）
- 避免事项（商务渐变、卡通图标、过度装饰等）

### 阶段 4：量化推进成果

**核心原则**：将成果抽象为工程语言

**用词规范：**

| ❌ 避免使用 | ✅ 推荐使用 |
|-----------|-----------|
| 学习了 | 完成了 |
| 研究了 | 验证了 |
| 了解了 | 建立了 |
| 模糊探索 | 分析了 |
|  | 设计了 |
|  | 实现了 |

**示例对比：**

**错误表达：**
> 学习了 QEMU

**正确表达：**
> 完成 QEMU 环境搭建与启动验证

**错误表达：**
> 研究了 StarryOS

**正确表达：**
> 完成 StarryOS 启动链分析，建立 QEMU 验证环境，形成基础测试框架

### 阶段 5：Codex 执行生成

**输入文件清单：**

```
template.pptx    # 定义背景与版式
outline.md       # 定义内容结构
style.md         # 定义视觉规范
assets/          # 素材（logo、截图等）
projspace/       # 真实项目工作区
```

**Codex 执行内容：**
- 操作 template.pptx
- 替换占位符
- 插入页面与图表
- 调整布局
- 自动生成结构化内容

## 四、图表设计规范

### 4.1 图表定位

> 图表不是装饰，而是工程表达工具。

**核心作用：**
- 解释系统结构
- 展示模块关系
- 体现工程复杂度
- 降低理解成本
- 建立系统工程感

### 4.2 推荐图表类型

#### DAG（有向无环图）
**适用场景：**
- 目录页
- 启动链 / 测试链
- 项目演化路径
- 后续规划

**表达能力：** 状态推进、系统演化、工程流程

#### Layered Architecture（分层架构图）
**适用场景：**
- 系统总体架构
- OS / Runtime 结构
- 硬件层次

**表达能力：** 系统层次、模块关系

#### Pipeline（管线流程图）
**适用场景：**
- QEMU 启动流程
- 烧录流程
- 控制流程
- 日志链路

**表达能力：** 输入 → 处理 → 输出

#### Tree（树结构）
**适用场景：**
- 成果树
- 问题树 / 风险树
- 模块树

**表达能力：** 系统拆解、工程复杂度

### 4.3 图表生成流程

1. 使用 ChatGPT 设计信息结构（确定 DAG 结构）
2. 使用 Codex 生成图表

### 4.4 图表风格规范

**风格描述要素：**
```
风格：
- 技术架构风
- 深色背景
- 极简扁平
- DAG 布局
- 信息密度高
- 少渐变
- 工程感强
```

## 五、页面设计原则

### 5.1 单页核心原则

> **一页只证明一件事**

避免一页同时讲述：
- 架构
- 进展
- 集成
- AI

应该每页聚焦一个核心观点。

### 5.2 内容结构

每页幻灯片应回答：
1. 什么问题？
2. 什么挑战？
3. 什么方案？
4. 已验证什么？
5. 下一步？

### 5.3 信息密度

- 采用中高信息密度
- 体现工程信息量
- 避免过度留白
- 避免元素随机分布

---

## 六、答辩节奏设计

### 6.1 时间分配（以 15 分钟为例）

**前 3 分钟：建立可信度**
- 项目背景与痛点
- 技术选型理由

**中间 8 分钟：建立技术深度**
- 系统架构
- 验证工作
- 技术分析

**最后 3 分钟：建立未来空间**
- 硬件适配计划
- 功能集成规划
- 应用场景展望

**剩余时间：问答环节**

### 6.2 迭代优化

**建议迭代轮次：**
- **第 1 轮**：结构与逻辑
- **第 2 轮**：强化成果表达（量化）
- **第 3 轮**：强化图表（系统感、架构感）
- **第 4 轮**：强化演讲（时间、节奏、重点）

## 七、质量检查清单

### 7.1 内容检查
- [ ] 避免流水账式叙述
- [ ] 避免功能堆叠展示
- [ ] 避免空泛概念
- [ ] 避免不切实际的承诺
- [ ] 每页有明确核心观点
- [ ] 成果已量化表达

### 7.2 视觉检查
- [ ] 图表风格统一
- [ ] 色彩系统一致
- [ ] 布局对齐规范
- [ ] 信息密度适中
- [ ] 避免过度装饰

### 7.3 表达检查
- [ ] 使用工程化语言
- [ ] 避免"学习了/研究了"等模糊表述
- [ ] 体现实事求是态度
- [ ] 展示系统推进过程
- [ ] 从评审角度审视内容

### 7.4 问答准备
- [ ] 提前预测评审可能提问的问题
- [ ] 准备技术细节支撑材料
- [ ] 准备运行截图与日志
- [ ] 准备测试数据与结果

## 八、常见问题与注意事项

### 8.1 内容陷阱
- ❌ 将过程写成流水账
- ❌ 炫耀功能而非展示能力
- ❌ 堆砌 AI 概念
- ❌ 夸大当前成果

### 8.2 视觉陷阱
- ❌ 商务渐变风格
- ❌ 卡通插画
- ❌ 营销风格
- ❌ 过度动画
- ❌ 玻璃拟态效果

### 8.3 表达陷阱
- ❌ 使用模糊动词（学习、了解、研究）
- ❌ 缺乏数据支撑
- ❌ 只有概念没有验证
- ❌ 缺少工程细节

---

## 九、总结

### 核心原则

> 一份优秀的技术答辩 PPT 应该像"一个正在推进中的系统工程项目"，而不是"功能堆叠型展示"。

### 五大要素
1. **实事求是**：不夸大、不虚构
2. **系统思维**：体现架构与层次
3. **阶段推进**：展示工程进展
4. **技术可信**：用数据和截图证明
5. **清晰表达**：用图说话，降低理解成本

### 工作流总结

```
项目梳理 → 受众分析 → 叙事策略
    ↓
定义目标 → 精炼大纲 → 定义风格
    ↓
量化成果 → AI 生成 → 迭代优化
    ↓
质量检查 → 问答准备 → 最终交付
```
