# Obsidian

> Obsidian 是基于 Markdown 的本地优先知识库工具，支持双向链接、插件扩展、图谱可视化。本文档涵盖知识库搭建方法、配置建议、插件使用和文档写作规范，帮助构建可持续积累的个人知识体系。

**关键词**：Obsidian、知识管理、双向链接、Markdown、本地优先、第二大脑

## 抽象类比

Obsidian 就像你的**第二大脑**。大脑之所以聪明，不是因为装了海量信息，而是因为神经元之间相互连接——看到一个概念能联想到另一个概念。Obsidian 的双向链接（`[[ ]]`）就是这些"神经元连接"，每条笔记都是神经元，链接就是突触。随着笔记增多，你的知识库会像大脑一样形成一张自生长的网络，越用越聪明。

---

## 为什么选 Obsidian

- **本地优先**：数据在本地，不依赖云端，安全可控
- **Markdown 格式**：通用性强，不绑定平台
- **双向链接**：`[[笔记名]]` 建立知识关联
- **插件生态**：高度可扩展
- **免费开源**：跨平台（Windows/Mac/Linux/移动端）

### 核心概念

- **笔记**：基本的 Markdown 文件
- **仓库（Vault）**：笔记的集合
- **双向链接**：`[[笔记名]]` 建立关联，支持反向链接
- **标签**：`#标签` 分类标记
- **图谱视图**：可视化笔记关系

## 知识库设计

### PARA 方法

PARA 是以行动为导向的知识组织系统，按可操作性排序：

| 层级 | 含义 | 特点 | 示例 |
| :--- | :--- | :--- | :--- |
| **P** Projects | 项目 | 有明确目标和截止日期 | "操作系统比赛"、"毕业论文" |
| **A** Areas | 领域 | 需要持续关注的责任区 | "技术学习"、"健康管理" |
| **R** Resources | 资源 | 感兴趣的主题和参考资料 | "AI 笔记"、"工具手册" |
| **A** Archives | 归档 | 已完成或不再活跃的内容 | "旧项目"、"过期文档" |

**PARA 工作流**：
```
新项目 → Projects（正在进行）
      ↓ 完成
    Archives（归档）

持续责任 → Areas（长期关注）
感兴趣主题 → Resources（参考资料）
```

**使用建议**：
1. 每周回顾：检查 Projects 是否有需要归档的
2. 新项目先放 Projects，完成后再决定移到哪里
3. Areas 不要太多（5-7 个为宜）
4. PARA 管结构，双向链接管关系

### 知识流转

```
收集 → 整理 → 内化 → 输出 → 归档
```

- **收集**：快速记录想法、摘抄、截图
- **整理**：分类、打标签、建立链接
- **内化**：重写成自己的话、添加思考
- **输出**：文章、PPT、代码、方案
- **归档**：过期内容移入 Archive

### 目录结构

```
obsidianDocument/
├── 00-Inbox/              # 收集箱（下载的未归类文档）
├── 学习/                  # 技术学习资料
├── 考研/                  # 考研复习资料
├── 工作效率/              # 工具、环境与效率方法
├── 个人成长/              # 个人思考与感悟
├── Assets/                # 附件（图片、PDF）
├── final/                 # 未归档内容
└── README.md              # 知识库说明
```

### 命名规范

- **文件命名**：统一中文命名，避免特殊字符 `/ \ : * ? " < > |`
- **排序前缀**：`00-`、`10-`、`20-` 等数字前缀控制排序

### MOC（内容地图）

MOC 是知识库的导航页，按主题组织相关笔记。

**创建步骤**：
1. 创建笔记，命名为 `XXX MOC.md`
2. 按主题分类，列出相关笔记链接
3. 添加简短描述
4. 定期更新

**最佳实践**：
- 一个主题一个 MOC
- 层级 2-3 层为宜
- 加简短说明，不只列链接
- 文件夹管大分类，MOC 管主题索引

## 配置建议

### 核心配置

- **附件文件夹**：`Assets/images`
- **实时预览**：开启
- **自动保存**：开启
- **主题**：Border（推荐）

### 必开核心插件

- ✅ 文件回收站、文件资源管理器、全局搜索
- ✅ 双向链接、标签面板、大纲
- ✅ 日记、模板

### 推荐社区插件

#### Templater（模板增强）

增强版模板插件，支持 JavaScript 脚本、用户输入、日期计算。

```
配置：
1. 设置 → 第三方插件 → 安装 Templater
2. Template folder location → Templates
3. 快捷键 → Ctrl+T
4. 勾选 "Trigger Templater on new file creation"
```

#### Excalidraw（绘图）

手绘风格图表，支持架构图、流程图、时序图，可嵌入笔记。

```
配置：
1. 社区插件搜索 Excalidraw
2. 设置绘图保存位置 → Excalidraw
3. 快捷键 → Alt+E 新建绘图
```

#### Dataview（数据查询）

查询和展示笔记数据，可做项目看板、任务列表。

```dataview
TABLE status, created
FROM "考研"
WHERE status = "进行中"
SORT created DESC
```

### 快捷键

| 快捷键 | 功能 |
| :--- | :--- |
| `Ctrl+T` | Templater 插入模板 |
| `Alt+E` | 新建 Excalidraw 绘图 |
| `Ctrl+O` | 快速打开笔记 |
| `Ctrl+P` | 命令面板 |

## 工作流

### 日常使用

1. **收集想法** → 写入 `00-Inbox`
2. **创建日记** → `Ctrl+T` 选择日记模板
3. **整理笔记** → 从 Inbox 移到对应目录

- [ ] 清理 `00-Inbox`
- [ ] 更新 `MOC.md`
- [ ] 检查 Projects 进度

## 工程型文档写作

### 核心原则

工程型文档 vs 传统文档：
- **目标**：解决问题（不是记录知识）
- **结构**：模块化拆解（不是线性叙述）
- **语言**：简洁直白（不是学术化）
- **验证**：数据证明（不是理论推导）
- **更新**：持续迭代（不是写完就放）

### 写作要点

- **问题导向**：每篇文档解决一个具体问题
- **结构清晰**：统一模板，降低阅读成本
- **数据驱动**：用数据、截图、日志证明
- **可复用**：模块化内容，可组合可迁移
- **版本管理**：Git 跟踪，可回溯

## 常见问题

- **模板不生效**：检查 Templater 插件是否启用，模板文件夹路径是否正确
- **双向链接找不到**：确保笔记名完全匹配
- **批量重命名**：Obsidian 重命名会自动更新所有链接

## 面试速答

### Q: Obsidian 和 Notion、飞书等云笔记的核心区别是什么？
A: Obsidian 是**本地优先**——所有笔记都是本地 Markdown 文件，不依赖云端，断网也能用、不会被锁定、数据完全可控。Notion/飞书是云端数据库，优势是协作，但数据不在自己手里、有被封号风险。Obsidian 用通用 Markdown 格式，十年后还能打开；云笔记的私有格式一旦平台倒闭就麻烦了。

### Q: 什么是双向链接？和普通超链接有什么区别？
A: 普通超链接是单向的——A 链接到 B，B 不知道。Obsidian 的双向链接 `[[笔记名]]` 是双向的——A 链接到 B 后，B 的反向链接面板会自动显示"A 引用了我"。这让知识之间形成网状关联，发现意想不到的连接，是构建"第二大脑"的核心机制。

### Q: PARA 方法是什么？为什么按可操作性分类？
A: PARA 按"可操作性"把知识分成四层：Projects（有截止日期的项目）、Areas（持续关注的领域）、Resources（参考资料）、Archives（归档）。这样分类是因为：紧急的内容放 Projects，重要的内容放 Areas，感兴趣的放 Resources，过期的放 Archives——优先级一目了然，避免所有东西堆在一起找不到。

### Q: 什么时候用文件夹，什么时候用标签，什么时候用双向链接？
A: 三者分工不同：**文件夹**管大分类（PARA 顶层目录），**标签**管细分类（`#技术/AI` 跨目录标记），**双向链接**管知识点之间的语义关系（"指针"链到"内存管理"）。原则：文件夹管结构，标签管横切，链接管关系，不要混用。

### Q: Obsidian 适合做什么？不适合做什么？
A: 适合：个人知识库、学习笔记、项目文档、读书笔记、长期积累的资料。不适合：多人实时协作（用飞书/Notion）、富媒体编辑（用 Notion）、强结构化数据管理（用数据库）。Obsidian 强在个人深度思考和长期积累，弱在团队协作。

### Q: 新手入坑 Obsidian 的常见误区？
A: 三大误区：1) 一上来就装一堆插件，结果陷入"折腾工具"的怪圈，建议先用核心插件跑 1 个月再加；2) 过度追求目录结构完美，其实双向链接比目录更重要；3) 只收集不内化，把 Obsidian 当网盘用——笔记要用自己的话重写一遍才真消化了。
