# Markdown

> Markdown 是一种轻量级标记语言，用纯文本格式编写文档，可转换为 HTML、PDF、Word 等多种格式。本文介绍 Markdown 的基础语法、常用扩展和使用技巧，帮助快速编写结构化文档。

**关键词**：Markdown、标记语言、纯文本、文档编写、跨平台

## 抽象类比

Markdown 就像**简化版的写作语法**。它用我们日常写邮件、记笔记时就会用到的符号（`#`、`*`、`>`、`-`）来表达"这是标题""这是强调""这是引用""这是列表"，让写作时不必切换鼠标去点格式工具栏，双手不离键盘就能完成排版。可以理解为"用纯文本写出带格式文档"的通用约定。

## 一、介绍

### 1.1 什么是 Markdown

Markdown 是一种轻量级标记语言，使用纯文本格式编写文档。

**应用场景**：
- README 文档
- 技术文档
- 博客文章
- 笔记记录

### 1.2 优势

| 优势 | 说明 |
|------|------|
| 专注内容 | 不需要关注格式和排版 |
| 学习成本低 | 几分钟即可掌握基本语法 |
| 跨平台 | 所有文本编辑器都支持 |
| 可转换 | 可导出为 HTML、PDF、Word 等 |
| 版本控制 | Git 友好，diff 清晰 |

## 二、基本语法

### 2.1 标题

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

### 2.2 文本格式

```markdown
**粗体文本**
*斜体文本*
~~删除线~~
`行内代码`
```

### 2.3 列表

#### 无序列表
```markdown
- 项目 1
- 项目 2
  - 子项目 2.1
  - 子项目 2.2
- 项目 3
```

#### 有序列表
```markdown
1. 第一项
2. 第二项
3. 第三项
```

#### 任务列表
```markdown
- [x] 已完成任务
- [ ] 未完成任务
- [ ] 待办事项
```

### 2.4 链接与图片

```markdown
[链接名称](URL)
<URL>

![图片描述](图片路径)
![图片描述](图片路径 "图片标题")
```

### 2.5 引用

```markdown
> 这是一段引用文本
> 可以多行书写
> 
> > 嵌套引用
```

### 2.6 代码块

````markdown
```语言名称
代码内容
```

例：
```python
def hello():
    print("Hello, World!")
```
````

### 2.7 表格

```markdown
| 列 1 | 列 2 | 列 3 |
|------|------|------|
| 内容 | 内容 | 内容 |
| 内容 | 内容 | 内容 |
```

### 2.8 分隔线

```markdown
---
或
***
```

### 2.9 转义字符

```markdown
\* 不是斜体
\# 不是标题
\` 不是代码
```


## 面试速答

### Q: Markdown 适合什么样的场景？
A: 适合写 README、技术文档、博客、笔记、API 文档等结构化文本。核心优势是纯文本、学习成本低、跨平台、Git 友好、可转换为多种格式。不适合需要复杂排版（多栏、精细样式）的文档。

### Q: Markdown 和 Word 有什么区别？
A: Markdown 是纯文本标记语言，用符号表达格式，双手不离键盘，Git 友好，可转多种格式，但不支持复杂排版；Word 是所见即所得，鼠标操作，排版能力强，但文件是二进制，diff 不友好，协作容易冲突。写技术文档选 Markdown，写正式报告选 Word。

### Q: 为什么 Markdown 适合版本控制？
A: Markdown 是纯文本，Git 能清晰 diff 每次改动，合并冲突可手动解决。Word 文件是二进制，Git 无法看出具体改了什么，合并基本靠手动沟通。所以技术文档、README 基本都用 Markdown。

### Q: Markdown 有哪些常用扩展语法？
A: 常见扩展：数学公式（`$...$` 行内、`$$...$$` 块级）、任务列表（`- [x]`）、脚注（`[^1]`）、目录（`[TOC]`）、Mermaid 图表（` ```mermaid ` 代码块）、表格、删除线（`~~`）。不同编辑器/平台支持的扩展略有不同。

### Q: Markdown 常见误区有哪些？
A: 一是以为所有平台语法一致，实际上 GitHub Flavored Markdown、CommonMark、Typora 等扩展语法有差异；二是嵌套列表缩进混乱，导致解析错误；三是表格、代码块嵌套时忘记空行分隔。建议写完在不同平台预览确认。
