# Docker 入门

> 小白先读：Docker 是"容器化"工具，把应用和它需要的一切（代码、库、配置）打包在一起，在任何机器上都能一致运行。解决了"在我电脑上能跑"的问题。
>
> 学这篇时先抓 3 个问题：Docker 解决了什么问题？镜像和容器是什么？为什么 Docker 这么火？

## 先用一句生活话理解

Docker 像集装箱——不管里面装什么货物，集装箱的尺寸是标准的，任何港口、任何轮船都能运。

以前部署软件像搬家：要担心新家有没有煤气、有没有网线。Docker 像把整个房间打包带走，到哪都能直接住。

## 什么是 Docker？

想象你要开连锁餐厅：
- **不用 Docker**：每家店单独装修、单独采购、单独培训，口味可能不一样
- **用 Docker**：把整个厨房打包，每家店直接复制，口味完全一致

**简单说**：Docker 是**把应用和它的运行环境打包在一起**的工具，保证"一次打包，到处运行"。

---

## Docker 的设计哲学

Docker 诞生的核心问题：**"在我电脑上能跑，到你那就不行了"**

原因：
- 操作系统版本不同
- 依赖库版本不同
- 配置不同

Docker 的解决方案：**把应用和它需要的一切打包成镜像**，在任何机器上运行都一样。

---

## 核心概念

### 1. 镜像：菜谱

**类比**：镜像像一份完整的菜谱——食材、调料、做法都写好了。

镜像是一个只读的模板，包含：
- 操作系统
- 运行环境（Python、Node.js 等）
- 代码
- 依赖库

---

### 2. 容器：做出来的菜

**类比**：容器像用菜谱做出来的一份菜，可以运行、可以停止。

- **镜像**：菜谱（静态）
- **容器**：做出来的菜（运行中的实例）

一个镜像可以启动多个容器。

---

### 3. Dockerfile：自己写菜谱

**类比**：Dockerfile 像你自己写的菜谱，告诉 Docker 怎么构建镜像。

```dockerfile
FROM python:3.9           # 用 Python 3.9 环境
WORKDIR /app              # 工作目录
COPY . .                  # 复制代码
RUN pip install -r requirements.txt  # 安装依赖
CMD ["python", "app.py"]  # 启动命令
```

---

### 4. Docker Hub：菜谱大全

**类比**：Docker Hub 像菜谱网站，里面有别人写好的镜像，拿来就能用。

```bash
docker pull nginx         # 下载 nginx 镜像
docker run -d nginx       # 启动 nginx 容器
```

## Docker vs 虚拟机

| 维度 | Docker | 虚拟机 |
| :--- | :--- | :--- |
| **启动速度** | 秒级 | 分钟级 |
| **资源占用** | 小（共享内核） | 大（完整操作系统） |
| **隔离性** | 进程级 | 完全隔离 |
| **适合场景** | 微服务、CI/CD | 需要完全隔离 |

---

## Docker 的应用场景

| 场景 | 例子 | 为什么用 Docker |
| :--- | :--- | :--- |
| **微服务** | 每个服务一个容器 | 独立部署、扩展 |
| **CI/CD** | 自动化构建测试 | 环境一致 |
| **开发环境** | 新人一键启动 | 不用配环境 |
| **快速部署** | 云服务器 | 镜像直接跑 |

---

## 总结

### 三句话讲清楚 Docker

1. Docker 是容器化工具，把应用和运行环境打包在一起
2. 镜像是模板，容器是运行中的实例
3. 解决了"在我电脑上能跑"的问题，保证环境一致

### 核心类比

> Docker 像集装箱——不管里面装什么，集装箱尺寸标准，任何港口都能运。
