# Redis 入门

> 小白先读：Redis 是内存数据库，数据存在内存里，读写速度极快。常用来做缓存、排行榜、消息队列，是后端开发的高频工具。
>
> 学这篇时先抓 3 个问题：为什么要把数据放内存里？Redis 和 MySQL 有什么区别？Redis 适合什么场景？

## 先用一句生活话理解

Redis 像你的"草稿纸"——正在算的东西先记在草稿纸上，算完再写到正式本子上。草稿纸写得快、擦得快，但关机就没了。

MySQL 像正式笔记本，记录完整、持久，但翻找慢。Redis 像草稿纸，速度极快，但断电数据会丢。

## 什么是 Redis？

想象你要开餐厅：
- **MySQL**：像账本，记录所有订单，完整但翻找慢
- **Redis**：像收银台旁的小黑板，写着"当前最忙的 10 桌"，一眼就能看到

**简单说**：Redis 是**内存中的键值存储**，读写速度极快，常做缓存和实时数据处理。

---

## Redis 的设计哲学

Redis 诞生的核心问题：**数据库查询太慢，用户等不了**

解决方案：把频繁访问的数据放在内存里，不用每次都查数据库。

Redis 的核心信条：
- **内存优先**：数据存在内存，读写速度微秒级
- **简单键值**：key-value 模型，没有复杂的 SQL
- **丰富数据结构**：不只是字符串，还有列表、集合、有序集合等
- **持久化可选**：可以选择定期写入磁盘，防止断电丢失

---

## 核心概念

### 1. 键值存储：超级字典

**类比**：Redis 像一本超级字典，通过"词条名"（key）秒速找到"解释"（value）。

```
"user:1001" → "张三"
"product:888:price" → "99.9"
"hot:articles" → [文章1, 文章2, 文章3]
```

---

### 2. 丰富数据结构：不只是字符串

**类比**：Redis 不只能存文字，还能存列表、集合、排行榜。

| 数据类型 | 类比 | 适合场景 |
| :--- | :--- | :--- |
| **String** | 普通文本 | 缓存、计数器 |
| **List** | 排队列表 | 消息队列 |
| **Set** | 不重复的集合 | 标签、去重 |
| **Hash** | 小字典 | 对象存储 |
| **ZSet** | 带分数的排行榜 | 排行榜、优先级队列 |

---

### 3. 过期时间：自动清理

**类比**：像便利贴，写上"30 分钟后扔掉"，时间到了自动消失。

```redis
SET session:abc "用户数据" EX 1800  # 30 分钟后过期
```

常用于缓存、会话管理。

---

### 4. 发布订阅：消息广播

**类比**：像广播电台，有人 broadcasting，有人 listening。

```redis
PUBLISH news "今天天气不错"
SUBSCRIBE news  # 接收消息
```

---

## Redis 的应用场景

| 场景 | 用什么 | 为什么 |
| :--- | :--- | :--- |
| **缓存** | 热点数据缓存 | 减轻数据库压力 |
| **排行榜** | ZSet 有序集合 | 实时更新排名 |
| **计数器** | String 原子递增 | 点赞数、访问数 |
| **消息队列** | List | 任务异步处理 |
| **会话管理** | Session 存储 | 用户登录状态 |
| **分布式锁** | SETNX | 防止并发冲突 |

---

## Redis vs MySQL

| 维度 | Redis | MySQL |
| :--- | :--- | :--- |
| **存储位置** | 内存 | 磁盘 |
| **速度** | 极快（微秒级） | 较慢（毫秒级） |
| **数据量** | 有限（受内存限制） | 海量 |
| **持久化** | 可选 | 默认持久 |
| **查询能力** | 简单键值 | 复杂 SQL |
| **适合场景** | 缓存、实时数据 | 核心业务数据 |

---

## 总结

### 三句话讲清楚 Redis

1. Redis 是内存数据库，读写速度极快
2. 支持丰富数据结构，不只是简单键值
3. 常做缓存、排行榜、消息队列，是后端必备工具

### 核心类比

> Redis 像"草稿纸"——正在算的东西先记在草稿纸上，速度极快。MySQL 像正式笔记本，完整但慢。
