# 软件工程入门

> 小白先读：软件工程研究的是"怎么开发大型软件项目"。写代码容易，但多人协作、长期维护、保证质量很难。软件工程就是解决这些问题的方法论。
>
> 学这篇时先抓 3 个问题：为什么需要软件工程？软件开发生命周期是什么？敏捷和瀑布有什么区别？

## 先用一句生活话理解

软件工程像建筑工程管理——一个人盖茅草屋不需要图纸，但盖摩天大楼需要设计、施工、监理、验收全套流程。

写个小脚本不需要软件工程，但开发微信、淘宝这种大型系统，没有工程化管理就会一团糟。

## 什么是软件工程？

想象你要盖一栋楼：
- **自己盖茅草屋**：想怎么盖就怎么盖，不需要规划
- **请施工队盖别墅**：需要图纸、工期、验收
- **开发大型软件**：需要需求分析、设计、编码、测试、维护

**简单说**：软件工程是**用工程化的方法开发和维护软件**的学科。

---

## 软件工程的设计哲学

软件工程的核心问题是：**如何在"质量"、"成本"、"时间"之间取得平衡？**

三种经典模型：
- **瀑布模型**：按部就班，需求 → 设计 → 编码 → 测试 → 维护
- **敏捷开发**：快速迭代，小步快跑，拥抱变化
- **DevOps**：开发和运维一体化，持续交付

选择取决于项目：
- 需求明确、不能变？用瀑布
- 需求不确定、要快速验证？用敏捷
- 要快速交付、持续更新？用 DevOps

---

## 核心概念

### 1. 软件开发生命周期

**类比**：像盖楼的全过程——规划 → 设计 → 施工 → 验收 → 维护。

| 阶段 | 做什么 | 产出 |
| :--- | :--- | :--- |
| **需求分析** | 搞清楚要做什么 | 需求文档 |
| **设计** | 规划怎么做 | 设计文档 |
| **编码** | 写代码实现 | 源代码 |
| **测试** | 检查有没有 bug | 测试报告 |
| **维护** | 修复问题、添加功能 | 更新版本 |

---

### 2. 敏捷开发：小步快跑

**类比**：像做 MVP——先做一个能用的版本，根据反馈快速迭代。

敏捷的核心：
- **迭代**：每 1-4 周交付一个可用版本
- **响应变化**：需求变了？没关系，快速调整
- **团队协作**：每天站会，及时沟通
- **客户参与**：让客户看到进度，及时反馈

**代表框架**：Scrum、Kanban、XP

---

### 3. 版本控制：时光机

**类比**：像游戏的存档功能，随时可以回到之前的版本。

版本控制工具（Git）让你：
- 记录每次修改
- 多人协作不冲突
- 随时回滚到历史版本
- 分叉开发不同功能

---

### 4. 测试：质量保障

**类比**：像汽车出厂前的质检——每个零件都要检查，整车也要路测。

测试层次：
- **单元测试**：检查单个函数
- **集成测试**：检查模块之间的配合
- **系统测试**：检查整个系统
- **验收测试**：客户确认是否满足需求

---

## 软件工程的应用场景

| 场景 | 用什么 | 为什么 |
| :--- | :--- | :--- |
| **大型项目** | 瀑布/敏捷 | 多人协作、长期维护 |
| **创业公司** | 敏捷/MVP | 快速验证、拥抱变化 |
| **开源项目** | Git + 敏捷 | 分布式协作 |
| **企业系统** | DevOps | 持续交付、快速迭代 |

---

## 总结

### 三句话讲清楚软件工程

1. 软件工程是用工程化的方法开发和维护软件
2. 核心是平衡质量、成本、时间，选择合适的开发模型
3. 敏捷开发、版本控制、测试是 modern 软件的标配

### 核心类比

> 软件工程像建筑工程管理——一个人盖茅草屋不需要图纸，但盖摩天大楼需要全套流程。
