# 协议总结

> 协议是通信双方约定好的一套规则，规定了双方"对话"的格式、含义与顺序。无论是浏览器访问网页、两台服务器传文件，还是传感器把数据发到云平台，背后都靠协议保证双方能"听懂"对方。本文系统梳理网络协议的三要素、分层模型、常见协议与设计要点。

**关键词**：通信协议、语法语义时序、OSI 模型、TCP/IP、HTTP、可靠性

## 抽象类比

协议可以类比成"两个人说话要用同一种语言和礼貌"：你说中文我听中文、你问"你好吗"我答"我很好"、你先说我后答——这种对语言、含义、顺序的共同约定，就是协议。换到计算机世界，无非是把"说话"换成了"发数据包"，规则的本质不变：用同一种格式、约定好含义、按既定顺序一来一往，双方才能听懂彼此。

## 适合人群 / 预备知识

- 软件工程专业学生，想系统梳理网络与通信协议
- 了解基本编程概念即可，不要求精通某门语言
- 知道 IP 地址、端口号大概是什么最好，不知道也能看懂
- 适合准备面试、做后端 / 嵌入式 / 物联网方向的同学

## 一、协议的三要素

- 语法（Syntax）：数据的格式长什么样，比如"请求行 + 头部 + 空行 + 正文"
- 语义（Semantics）：每一段字段代表什么含义，比如"200 表示成功，404 表示找不到"
- 时序（Timing）：通信的顺序和节奏，比如"先发请求再回响应""超时多久重传"

三者缺一不可：只有格式没有含义是乱码，有含义没有顺序会乱套。

## 二、网络协议栈

OSI 七层模型是理论标准，TCP/IP 四层模型是工程实际，二者对应关系如下：

- 应用层（HTTP、FTP、DNS） → 对应 OSI 应用层 + 表示层 + 会话层
- 传输层（TCP、UDP） → 对应 OSI 传输层
- 网络层（IP、ICMP） → 对应 OSI 网络层
- 网络接口层（以太网、Wi-Fi） → 对应 OSI 数据链路层 + 物理层

数据在发送时从上往下逐层"封装"，每层加上自己的头部；接收时从下往上逐层"解封装"，剥掉头部还原出原始数据。这种设计让每一层只关心自己的事，互不干扰。

## 三、应用层协议

应用层协议直接面向用户程序，决定了"用什么姿势通信"。

- HTTP：超文本传输协议，网页浏览的核心，默认端口 80
- HTTPS：HTTP + TLS 加密，防窃听防篡改，默认端口 443
- WebSocket：在一条 HTTP 连接上实现双向实时通信，适合聊天、推送
- DNS：把域名解析成 IP 地址，默认端口 53
- FTP：文件传输协议，控制连接 21、数据连接 20
- SMTP：发送邮件，默认端口 25 / 465（加密）
- POP3：接收邮件到本地，默认端口 110 / 995（加密）
- IMAP：在服务器上直接管理邮件，默认端口 143 / 993（加密）
- SSH：加密远程登录，默认端口 22
- Telnet：远程登录，明文传输，已基本被 SSH 淘汰
- DHCP：自动分配 IP 地址，默认端口 67 / 68
- NTP：网络时间同步，默认端口 123

## 四、传输层协议

传输层负责端到端的数据传递，决定了"可靠还是快"。

- TCP：面向连接、可靠传输，保证数据不丢不乱不重
  - 三次握手建立连接，四次挥手断开连接
  - 类比"打电话，先确认对方在听，没听清就重说"
  - 适合网页、邮件、文件传输
- UDP：无连接、不可靠，但延迟低、开销小
  - 类比"广播喊话，喊出去就不管了，听没听到随缘"
  - 适合视频直播、游戏、DNS 查询
- QUIC：基于 UDP 的现代协议，HTTP/3 的基础
  - 把 TLS 加密和连接管理合并，握手更快
  - 解决了 TCP 在弱网下队头阻塞的问题

```mermaid
sequenceDiagram
    participant C as 客户端
    participant S as 服务端
    C->>S: SYN（我想建立连接）
    S->>C: SYN+ACK（好的，我也确认）
    C->>S: ACK（收到，开始通信）

```

## 五、网络层协议

网络层负责"跨网络把包送到目的地"。

- IP 协议：给每台设备分配地址，负责路由转发
  - IPv4：32 位地址，如 192.168.1.1，已基本耗尽
  - IPv6：128 位地址，如 2001:db8::1，几乎用不完
- ICMP：互联网控制报文协议，ping 命令用的就是它
- ARP：把 IP 地址解析成 MAC 地址，局域网通信必经一步
- 路由协议：路由器之间交换路由信息
  - OSPF：内部网关协议，基于链路状态
  - BGP：外部网关协议，连接不同自治系统，是互联网的骨干
- NAT：网络地址转换，让多台设备共用一个公网 IP

## 六、数据链路层与物理层

这两层负责"在一段链路上把比特搬过去"。

- 以太网：最常见的局域网技术，帧格式为 Ethernet II
- MAC 地址：网卡的物理地址，48 位，局域网内寻址用
- Wi-Fi（IEEE 802.11）：无线局域网标准
- 交换机：工作在数据链路层，按 MAC 地址转发帧
- 集线器 / 中继器：工作在物理层，单纯放大和转发电信号
- CSMA/CD：有线以太网的冲突检测机制
- CSMA/CA：无线 Wi-Fi 的冲突避免机制

## 七、通信协议（非网络）

不是所有协议都走互联网，很多场景下设备之间也需要约定规则。

- RPC：远程过程调用，让调用远程服务像调用本地函数一样
- gRPC：Google 开源的 RPC 框架，基于 HTTP/2 和 Protobuf
- MQTT：物联网轻量协议，发布订阅模式，适合带宽小、设备多的场景
- CoAP：物联网资源协议，类似"物联网版的 HTTP"，基于 UDP
- Modbus：工业现场总线协议，常用于 PLC 和仪表通信
- CAN：汽车和工业控制总线，抗干扰强
- I2C / SPI / UART：嵌入式常用串行通信协议，详见 [[嵌入式系统]] 目录下的相关笔记

```mermaid
graph LR
    PUB[发布者] --> B[Broker 代理]
```

## 八、安全与认证协议

安全协议解决"怎么确认你是你、数据不被偷看"的问题。

- TLS / SSL：在传输层之上加密通信，HTTPS、SMTPS 等都依赖它
- OAuth 2.0：授权框架，"用微信登录 XX 应用"就是它
- JWT：JSON Web Token，把用户信息编码成一段令牌，无状态认证
- SAML：基于 XML 的单点登录协议，企业 SSO 常用
- Kerberos：基于票据的域认证协议，Windows 域环境核心
- mTLS：双向 TLS，客户端和服务端互相验证证书

## 十、面试 Q&A

- Q1：TCP 三次握手为什么不是两次？
  - A：两次握手只能确认"客户端能收到服务端的包"，但服务端无法确认"客户端能收到自己的包"。三次握手让双方都确认了收发能力，同时防止历史连接请求被误当成新连接，造成资源浪费。

- Q2：TCP 和 UDP 有什么区别？
  - A：TCP 面向连接、可靠、有序、有流量控制和拥塞控制，适合对数据完整性要求高的场景；UDP 无连接、不可靠、开销小、延迟低，适合实时性要求高、能容忍少量丢包的场景。

- Q3：HTTP 和 HTTPS 有什么区别？
  - A：HTTP 明文传输，数据可被窃听篡改；HTTPS = HTTP + TLS，在 TCP 之上加密通信，还通过证书验证服务器身份。HTTPS 多一次 TLS 握手，性能略有损耗，但安全性大幅提升，现代网站基本都强制 HTTPS。

- Q4：为什么 DNS 既要走 TCP 又要走 UDP？
  - A：DNS 查询报文通常很短，用 UDP 更快更省资源；但当响应数据超过 512 字节（如区域传输）或 UDP 不稳定时，会切换到 TCP 保证可靠性。

## 十一、如何向他人解释

跟非技术朋友解释协议，可以这样讲：

假设你要给国外的朋友寄信。你们得先约定好一些事情：用什么语言写、信封怎么填、地址写在哪一行、邮票贴多少。如果约定不一致，信就寄不到或者看不懂——这套约定就是"协议"。

在计算机世界里也是一样：

- 两台电脑要传文件，得约定数据按什么格式打包（这是 FTP 协议）
- 浏览器要看网页，得约定请求和响应长什么样（这是 HTTP 协议）
- 要加密别让人偷看，得约定怎么握手、怎么加密（这是 HTTPS）

每一层协议各管一段：物理层管电信号、网络层管地址和路由、传输层管可靠送达、应用层管具体业务。它们一层层叠起来，就组成了我们每天都在用的互联网。
