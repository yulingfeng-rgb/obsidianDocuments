# 结构化输出：让 AI 按格式说话

> 小白先读：结构化输出是让 AI 不只输出一段自然语言，而是输出固定格式的数据（如 JSON、表格），让程序能可靠地读取和处理。它是 AI 应用稳定性的关键。
>
> 学这篇时先抓 3 个问题：为什么 AI 输出需要结构化？怎么保证 AI 每次都按格式输出？结构化输出有什么应用场景？

## 先用一句生活话理解

你不是让别人随便写一段描述，而是让他填表：姓名、日期、问题、建议，一栏都不能乱。结构化输出就是这个道理——让 AI 按固定格式输出，而不是自由发挥。

**核心价值**：让 AI 的输出可预测、可解析、可自动化处理。

## 什么是结构化输出？

**一句话定义**：结构化输出是**让大语言模型按照预定义的格式（如 JSON、XML、表格）输出数据的技术**，确保输出结果能被程序可靠地读取和处理。

### 生活比喻

- **非结构化输出**：像写作文，自由发挥但格式不固定
- **结构化输出**：像填表格，每栏都有明确要求，格式固定

**简单说**：结构化输出 = 定义格式 → AI 按格式填充 → 程序可靠解析

---

## 为什么需要结构化输出？

### AI 自由输出的问题

| 问题 | 现象 | 影响 |
|------|------|------|
| **格式不稳定** | 每次输出格式不同 | 程序无法可靠解析 |
| **缺少字段** | 有时输出这个字段，有时不输出 | 数据处理出错 |
| **类型错误** | 应该输出数字，输出文字 | 程序报错 |
| **多余内容** | 输出包含解释性文字 | 需要额外清理 |
| **难以汇总** | 多条输出格式不一致 | 无法批量处理 |

### 结构化输出的核心价值

1. **可解析性**：程序能可靠地读取和处理
2. **稳定性**：每次输出格式一致
3. **自动化**：无需人工干预即可处理
4. **可验证**：能检查输出是否符合要求

**类比**：结构化输出像给 AI 一个"填空题"，而不是"问答题"。

## 结构化输出的实现方式

### 1. Prompt 工程

**方法**：在提示词中明确要求输出格式

**示例**：
```
请分析这段文本的情感，并按以下 JSON 格式输出：
{
  "sentiment": "positive/negative/neutral",
  "confidence": 0.0-1.0,
  "key_points": ["要点1", "要点2"]
}

文本：今天天气真好，心情很愉快！
```

**优点**：简单直接，无需额外工具
**缺点**：不保证 100% 遵守

### 2. Schema 约束

**方法**：使用 JSON Schema 等格式约束

**示例**：
```json
{
  "type": "object",
  "properties": {
    "name": {"type": "string"},
    "age": {"type": "integer", "minimum": 0},
    "email": {"type": "string", "format": "email"}
  },
  "required": ["name", "age", "email"]
}
```

**优点**：格式严格，可验证
**缺点**：需要支持 Schema 的模型或工具

### 3. 函数调用

**方法**：通过函数定义约束输出

**示例**：
```python
def extract_person_info(
    name: str,
    age: int,
    email: str
) -> dict:
    """提取人员信息"""
    pass
```

**优点**：类型安全，IDE 友好
**缺点**：需要编程知识

### 4. 专用工具

**方法**：使用专门的结构化输出工具

**例子**：
- OpenAI 的 `response_format` 参数
- Instructor 库
- LangChain 的结构化输出

**优点**：可靠性高，自动重试
**缺点**：依赖特定工具

## 结构化输出的典型应用

### 1. 信息提取

**场景**：从文本中提取结构化信息

**示例**：
```json
{
  "entities": [
    {"type": "person", "name": "张三", "age": 30},
    {"type": "company", "name": "ABC 公司"}
  ],
  "relationships": [
    {"from": "张三", "to": "ABC 公司", "type": "works_at"}
  ]
}
```

### 2. 数据分类

**场景**：对内容进行分类标注

**示例**：
```json
{
  "category": "技术",
  "subcategories": ["人工智能", "机器学习"],
  "confidence": 0.92,
  "tags": ["AI", "ML", "深度学习"]
}
```

### 3. 报告生成

**场景**：生成结构化的测试报告、分析报告

**示例**：
```json
{
  "test_results": [
    {"test_name": "启动测试", "status": "pass", "duration_ms": 1500},
    {"test_name": "推理测试", "status": "fail", "error": "超时"}
  ],
  "summary": {
    "total": 10,
    "passed": 8,
    "failed": 2,
    "pass_rate": 0.8
  }
}
```

### 4. API 响应

**场景**：AI 服务返回结构化数据

**示例**：
```json
{
  "answer": "北京今天晴天",
  "sources": ["天气 API"],
  "confidence": 0.95,
  "timestamp": "2024-01-01T10:00:00Z"
}
```

### 5. 工作流数据

**场景**：Agent 工作流中的数据传递

**示例**：
```json
{
  "step": "analysis",
  "input": {"data": "..."},
  "output": {"result": "..."},
  "next_step": "report"
}
```

## 结构化输出的最佳实践

### 1. 明确定义格式

**要点**：
- 使用 JSON Schema 等标准格式
- 明确字段类型和约束
- 提供示例输出

### 2. 验证输出

**要点**：
- 检查输出是否符合 Schema
- 处理格式错误的情况
- 自动重试或修正

### 3. 错误处理

**要点**：
- 捕获解析错误
- 提供友好错误信息
- 记录错误日志

### 4. 渐进式约束

**要点**：
- 先宽松后严格
- 根据场景调整约束
- 平衡灵活性和稳定性

## 结构化输出与其他概念的关系

### 与 Tool Calling 的关系

- **Tool Calling**：调用工具时传递参数
- **结构化输出**：工具返回结果的格式

**关系**：Tool Calling 需要结构化输出来保证结果可解析。

### 与 Agent 的关系

- **结构化输出**：单次输出的格式控制
- **Agent**：多次交互的工作流

**关系**：Agent 的每一步都需要结构化输出保证稳定性。

### 与 RAG 的关系

- **RAG**：检索增强生成
- **结构化输出**：RAG 结果的格式

**关系**：RAG 返回的文档列表和引用需要结构化输出。

## 总结

### 三句话讲清楚结构化输出

1. 结构化输出是让 AI 按照预定义的固定格式（如 JSON、表格）输出数据的技术，确保程序能可靠解析
2. 它通过 Prompt 工程、Schema 约束、函数调用等方式实现，让 AI 输出可预测、可验证、可自动化处理
3. 核心应用包括信息提取、数据分类、报告生成、API 响应等 AI 应用场景

### 核心类比

> 非结构化输出像写作文自由发挥但格式不固定，结构化输出像填表格每栏都有明确要求格式固定，让程序能可靠读取。
