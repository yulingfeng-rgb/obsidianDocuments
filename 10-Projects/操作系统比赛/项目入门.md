> **目标**: 让刚接触这个项目的同学,理解项目是怎么从0到1跑起来的

## 一、这个项目到底是什么?

### 1.1 一句话理解

**这是一个将基于 Linux 的自主网球拾取机器人系统，完整迁移至基于 Rust 语言的 Starry OS，并进行性能优化的竞赛项目。**

就像你教一个小朋友捡球:
- **眼睛**: 看到球在哪里 (摄像头+AI识别)
- **大脑**: 决定怎么走 (决策系统)
- **腿**: 走过去 (电机控制)
- **手**: 捡起来 (机械臂控制)

### 1.2 为什么要做这个项目?

**打个比方:**

原来机器人跑在 **Linux** 上,就像让机器人背着一个大书包:
- 书包很重 (启动慢,要等30秒)
- 占很多空间 (内存占用150MB)
- 耗电快 (功耗8瓦)

现在我们给它换上 **StarryOS**,就像换成轻便小背包:
- 很轻 (启动快,只要10秒)
- 占空间小 (内存只要100MB)
- 省电 (功耗只要6瓦)

**核心目标**: 让机器人启动更快、运行更省电、反应更灵敏!

### 1.3 赛题背景

本赛题是**"面向边缘智能的 AIOS 设计与优化"**（赛题编号：proj4），属于功能挑战赛道，由麒麟软件有限公司维护。

**技术栈：**
- **应用场景**：具身智能（自主网球拾取机器人）
- **硬件平台**：RK3588 处理器开发板
- **操作系统**：StarryOS（基于 Rust 语言）

**关键技术点：**
| 技术领域 | 具体任务 |
|----------|----------|
| 系统移植 | Linux → Starry OS 完整迁移 |
| 系统调用 | 实现/补全系统调用接口 |
| NPU 驱动 | NPU 推理链路打通 |
| 文件接口 | 实现文件系统接口 |
| USB 驱动 | 支持机器人机械臂感知 |
| UART 驱动 | 串口支持机械臂电机 |
| 摄像头驱动 | 视觉感知支持 |

## 四、LeRobot框架: 机器人的"标准接口"（可选）

### 4.1 什么是LeRobot?

**LeRobot是Hugging Face开发的开源机器人学习框架，基于 PyTorch。**

**官方定位**:
> "LeRobot aims to provide models, datasets, and tools for real-world robotics in PyTorch. The goal is to lower the barrier to entry so that everyone can contribute to and benefit from shared datasets and pretrained models."

**打个比方:**

如果没有LeRobot,就像你要自己发明一套"手脚协调系统":
- ❌ 要自己写怎么控制机械臂
- ❌ 要自己处理传感器数据
- ❌ 要自己实现运动学计算
- ❌ 要自己管理训练数据
- ❌ 每个机器人都要重新开发

有了LeRobot,就像有了"标准化的机器人接口":
- ✅ 统一的控制接口（硬件无关）
- ✅ 现成的策略网络（ACT、Diffusion、VLA等）
- ✅ 完善的数据集工具（LeRobotDataset 格式）
- ✅ 社区支持和持续更新

### 4.2 LeRobot在这个项目中干什么?

**核心作用: 提供机器人学习和控制的框架（可选使用）**

```
LeRobot的功能:
  📦 机器人抽象 - 统一的控制接口（支持 LeKiwi、SO100 等）
  🧠 策略网络 - 支持多种控制策略（ACT、Diffusion、VLA）
  📊 数据集管理 - LeRobotDataset 格式（Parquet + MP4）
  🎓 训练框架 - 模仿学习、强化学习
  🖥️ 部署工具 - lerobot-rollout、lerobot-eval 等 CLI 工具
```

**在项目中的位置:**
```
应用层 (Desktop-Wanderer)
  ↓ 可选使用
LeRobot框架
  ↓ 控制
硬件 (机械臂、电机)
```

**Desktop-Wanderer 官方文档说明**:
> "在PC上进行调试需要安装lerobot平台，具体安装方法可以参考 lerobot_Installation"

### 4.3 LeRobot怎么训练学习?

**就像一个学生学捡球:**

```
第1步: 看老师演示 (录制演示数据)
  ↓
  人遥控机器人捡10次球
  记录每次的: 看到什么、怎么动
  使用: lerobot-record --robot=lekiwi
  
第2步: 自己练习 (训练策略网络)
  ↓
  AI学习这些演示数据
  找出规律: "看到球在这个位置 → 应该这样动"
  使用: lerobot-train --policy=act --dataset.repo_id=...
  
第3步: 自己尝试 (执行策略)
  ↓
  机器人自己看到球
  用学到的策略决定怎么动
  自己完成捡球!
  使用: lerobot-rollout --policy.path=... --robot=lekiwi
```

### 4.4 为什么用LeRobot?

**三个原因:**

1. **官方支持**
   - Hugging Face开发和维护
   - 活跃的社区（Discord、中文教程）
   - 持续更新和改进（ICLR 2026 论文）

2. **标准化**
   - 统一的机器人接口（支持多种硬件）
   - 多种策略网络可选（ACT、Diffusion、VLA）
   - 数据集格式标准（LeRobotDataset）

3. **节省时间**
   - 不用从头开发控制逻辑

   - 专注于应用层功能

**总结: LeRobot让我们站在巨人的肩膀上,专注于项目核心创新!**

## 五、Desktop-Wanderer: 网球拾取应用

### 5.1 什么是 Desktop-Wanderer?

**Desktop-Wanderer 是一个基于视觉引导的移动操作机器人系统，能够自主搜索、跟踪和抓取网球。**

**官方定位**:
> "一个基于视觉引导的小型机器人系统，实现了自主目标检测、导航和抓取功能"

### 5.2 核心功能

| 特性 | 描述 |
|------|------|
| 🎯 视觉目标检测 | 基于 YOLO 神经网络实时检测网球，支持 50 FPS |
| 🤖 自主导航 | 视觉伺服控制，自动导航至目标位置 |
| 🦾 双模式机械臂 | ACT 模式（端到端学习）和逆运动学模式（P控制） |
| ⚡ 实时控制 | 20/50 FPS 精确控制循环 |
| 📦 智能放球 | 抓取后自动寻找桶并放置 |

### 5.3 状态机设计

**官方状态机**（来自 `src/setup.py`）:

```
┌─────────┐    ┌─────────┐    ┌──────────────┐    ┌──────────┐    ┌─────────┐
│ SEARCH  │───▶│  PICK   │───▶│ FIND_BUCKET  │───▶│ PUT_BALL │───▶│ SEARCH  │
└─────────┘    └─────────┘    └──────────────┘    └──────────┘    └─────────┘
```

**各状态详细说明**:

#### 1. SEARCH（找球模式）
- **进入条件**：系统启动后初始状态 / PUT_BALL 完成后返回
- **行为**：
  - 使用 `move_controller()` 控制底盘移动
  - 调用 `yolo_infer()` 进行目标检测（找球）
  - 检测到球并在视野中央**稳定 10 帧**后进入 PICK 状态

#### 2. PICK（捡球模式）
- **进入条件**：SEARCH 状态下检测到球并稳定 10 帧
- **行为**：使用 `p_control_loop()` 执行 `CATCH_ACTION` 动作序列

**官方 CATCH_ACTION 序列**（12 步）:
```python
CATCH_ACTION = [
    ("move_to", (0.0989, 0.125)),    # 移动到初始位置
    ("shoulder_pan", -12),            # 肩部旋转
    ("gripper", 60),                   # 张开夹爪
    ("wrist_flex", 80),               # 腕部弯曲
    ("move_to", (0.140, 0.1211)),     # 移动到球上方
    ("move_to", (0.140, -0.05)),      # 下降到球位置
    ("gap", 0),                        # 停顿
    ("gripper", -60),                  # 闭合夹爪（夹住球）
    ("gap", 0),                        # 停顿
    ("shoulder_pan", 12),              # 肩部归位
    ("move_to", (-0.1, 0.2)),          # 举起球
    ("wrist_flex", -20)                # 腕部配合
]
```

#### 3. FIND_BUCKET（找桶模式）
- **进入条件**：PICK 状态动作序列执行完成
- **行为**：
  - 检查夹爪是否仍然夹住球（`gripper_pos > 25`）
  - 如果球丢失，返回 SEARCH 状态重新寻找
  - 使用 `move_controller_for_bucket()` 控制底盘移动
  - **找桶策略**：优先检测黑色桶，找不到则检测红色桶

#### 4. PUT_BALL（放球模式）
- **进入条件**：FIND_BUCKET 状态下检测到桶并稳定 10 帧
- **行为**：使用 `p_control_loop()` 执行 `PUT_ACTION` 动作序列

**官方 PUT_ACTION 序列**（6 步）:
```python
PUT_ACTION = [
    ("shoulder_lift", 50),      # 抬起机械臂
    ("gap", 0),                  # 停顿
    ("gripper", 60),             # 张开夹爪（放球）
    ("gap", 0),                  # 停顿
    ("move_to", (-0.1, 0.2)),    # 收回机械臂
    ("gripper", -60),            # 闭合夹爪
]
```

### 5.4 配置文件

**官方 `config.yaml`**:
```yaml
port: /dev/ttyACM0          # 串口端口
fps: 20                     # 控制频率 (Hz)
log_level: INFO             # 日志级别
hardware_mode: normal       # 硬件模式: normal, 310b, rk3588
control_mode: inverse       # 控制模式: inverse, act
```

**硬件模式说明**:
| 模式 | 描述 | 推理后端 | 适用场景 |
|------|------|----------|----------|
| `normal` | CPU 模式 | ONNX Runtime | 开发调试 |
| `310b` | Atlas 310B | AscendCL | 边缘部署 |
| `rk3588` | 瑞芯微 RK3588 | RKNN | **比赛使用** |

**控制模式说明**:
| 模式 | 描述 | 特点 |
|------|------|------|
| `inverse` | 逆运动学模式 | 基于 P 控制的 12 步抓取序列 |
| `act` | ACT 模式 | 基于 Action Chunking Transformer 的端到端学习 |

## 六、性能优化：如何超越 Linux

4. 解决启动过程中的问题

**验收标准：**
- ✅ Starry OS 成功启动
- ✅ NPU 模型推理功能正常

#### 阶段 2：驱动完善与功能实现

**目标：** 实现外设驱动，完成网球拾取功能

**关键任务：**
1. 实现/完善 USB 驱动（支持机械臂感知）
2. 实现串口驱动（支持机械臂电机控制）
3. 完成摄像头驱动
4. 实现完整的网球拾取流程

**验收标准：**
- ✅ 机械臂能够正常感知环境
- ✅ 机械臂能够成功抓取网球
- ✅ 机器人能够完成完整的拾取任务

#### 阶段 3：性能优化与超越

**目标：** 在性能、资源消耗和能耗上超越 Linux 基线

**优化维度：**

| 优化维度 | 具体指标 | 优化策略 |
|----------|----------|----------|
| 启动速度 | 系统加电后的启动时间 | 内核裁剪、驱动延迟加载、服务按需启动 |
| 识别能力 | 识别网球的距离/准确度 | 模型优化、视觉算法改进 |
| 推理性能 | 推理一帧所需时间 | NPU 优化、模型轻量化、内存访问优化 |
| 运动控制 | 机械臂定位和抓取速度 | 实时调度优化、控制算法优化 |
| 资源消耗 | 内存占用 | 内存管理优化、缓存策略改进 |
| 能耗效率 | 整体功耗 | 低功耗模式优化、动态电源管理 |

**验收标准：**
- ✅ 在多个关键指标上超越 Linux 基线
- ✅ 性能提升具有可量化的数据支撑

### 6.2 具体优化了哪些地方?

| 优化项 | Linux | StarryOS 目标 | 怎么做到的? |
|--------|-------|----------|------------|
| **启动速度** | 30秒 | <10秒 | 去掉不必要的服务，内核裁剪 |
| **内存占用** | 150MB | <100MB | 只保留需要的功能，内存管理优化 |
| **功耗** | 8瓦 | <6瓦 | 智能电源管理，低功耗模式 |
| **稳定性** | C语言(容易崩溃) | Rust语言(内存安全) | 换更安全的编程语言 |
| **推理性能** | CPU 推理 | NPU 加速 | RKNN-Toolkit2 + INT8 量化 |

### 6.3 为什么能优化?

**三个原因:**

1. **量身定制**
   - Linux是通用系统,什么功能都有
   - StarryOS只做机器人需要的事
   - 就像定制西装比成衣更合身

2. **去掉包袱**
   - Linux要支持几百种硬件
   - 我们只支持RK3588一种芯片
   - 轻装上阵,自然更快

3. **现代技术**
   - Rust语言比C语言更安全
   - 不会有内存泄漏、空指针这些问题
   - 就像自动挡比手动挡更智能

### 6.4 StarryOS 的技术优势

**基于官方 StarryOS 文档**:

1. **Linux 兼容性**
   - 实现了 150+ Linux 系统调用
   - 大部分 Linux 应用程序可以直接运行
   - 降低了迁移难度

2. **基于 ArceOS 框架**
   - 模块化设计，清晰的代码组织
   - 便于添加 RK3588 平台支持和设备驱动

3. **Rust 语言优势**
   - **内存安全**：编译期检查内存错误
   - **类型安全**：强类型系统减少运行时错误
   - **零成本抽象**：高级语言特性不带来性能损失
   - **并发安全**：所有权系统防止数据竞争

4. **单体架构**
   - 性能优化潜力大
   - 去除不必要的服务开销

### 8.3 NPU 模型转换流程

**在 PC 上使用 RKNN-Toolkit2 转换模型**:

```python
from rknn.api import RKNN

# 1. 创建 RKNN 对象
rknn = RKNN(verbose=True)

# 2. 配置目标平台
rknn.config(
    mean_values=[123.675, 116.28, 103.53],
    std_values=[58.82, 58.82, 58.82],
    target_platform='rk3588'  # 比赛平台
)

# 3. 加载 Desktop-Wanderer 的 YOLO 模型
rknn.load_onnx(model='tennis.onnx')

# 4. 构建模型（INT8 量化）
rknn.build(
    do_quantization=True,
    dataset='./calibration_data.txt'
)

# 5. 导出 RKNN 模型
rknn.export_rknn('tennis.rknn')
```
