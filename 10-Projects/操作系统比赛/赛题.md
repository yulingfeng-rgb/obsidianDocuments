## 一、赛题概述

### 1.1 背景

边缘智能（Edge AI）技术快速发展，推动了 AIoT、无人系统、机器人等应用从实验室走向复杂场景。以基于 LeRobot 框架的自主网球拾取机器人为例，这类应用集成了高频视觉感知、实时决策与运动控制，对系统的实时性与资源利用率提出极高要求。

当前此类应用主要基于 Linux 等通用操作系统构建。尽管 Linux 凭借丰富的驱动与软件生态降低了开发门槛，但其通用架构带来的冗余服务开销、长执行路径开销、复杂调度开销以及大容量内存需求等，逐渐成为制约机器人端到端性能的瓶颈。

### 1.2 核心任务

将基于 **C 语言 Linux** 的开源网球拾取机器人系统，完整迁移至基于 **Rust 语言的 Starry OS**，并进行性能优化。

**技术栈：**
- **应用场景**：具身智能（自主网球拾取机器人）
- **硬件平台**：RK3588 处理器开发板
- **操作系统**：Starry（基于 Rust 语言）

### 1.3 关键技术点

| 技术领域 | 具体任务 |
|----------|----------|
| 系统移植 | Linux → Starry OS 完整迁移 |
| 系统调用 | 实现/补全系统调用接口 |
| NPU 驱动 | NPU 推理链路打通 |
| 文件接口 | 实现文件系统接口 |
| USB 驱动 | 支持机器人机械臂感知 |
| UART 驱动 | 串口支持机械臂电机 |
| 摄像头驱动 | 视觉感知支持 |

## 二、三个阶段目标

### 阶段 1：基础启动与模型加载

**目标：** Starry OS 在 RK3588 开发板上成功启动，并完成基本模型加载

**关键任务：**
1. 将 Starry OS 在 RK3588 平台启动
2. 使用 RKNN-Toolkit2 将 AI 模型转换为 RKNN 格式
3. 完成模型加载和推理
4. 解决启动过程中的问题

**验收标准：**
- Starry OS 成功启动
- NPU 模型推理功能正常

### 阶段 2：驱动完善与功能实现

**目标：** 实现外设驱动，完成网球拾取功能

**关键任务：**
1. 实现/完善 USB 驱动（支持机械臂感知）
2. 实现串口驱动（支持机械臂电机控制）
3. 完成摄像头驱动
4. 实现完整的网球拾取流程

**验收标准：**
- 机械臂能够正常感知环境
- 机械臂能够成功抓取网球
- 机器人能够完成完整的拾取任务

### 阶段 3：性能优化与超越

**目标：** 在性能、资源消耗和能耗上超越 Linux 基线

**优化维度：**

| 优化维度 | 具体指标 | 优化策略 |
|----------|----------|----------|
| 启动速度 | 系统加电后的启动时间 | 内核裁剪、驱动延迟加载、服务按需启动 |
| 识别能力 | 识别网球的距离/准确度 | 模型优化、视觉算法改进 |
| 推理性能 | 推理一帧所需时间 | NPU 优化、模型轻量化、内存访问优化 |
| 运动控制 | 机械臂定位和抓取速度 | 实时调度优化、控制算法优化 |
| 资源消耗 | 内存占用 | 内存管理优化、缓存策略改进 |
| 能耗效率 | 整体功耗 | 低功耗模式优化、动态电源管理 |

**验收标准：**
- 在多个关键指标上超越 Linux 基线
- 性能提升具有可量化的数据支撑
