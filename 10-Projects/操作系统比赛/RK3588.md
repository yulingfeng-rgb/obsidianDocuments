# RK3588 主板说明文档

## 一、项目概述

RK3588 是瑞芯微（Rockchip）的一款高性能 ARM 架构系统级芯片（SoC），用于边缘计算、人工智能和物联网应用。

### 1.1 芯片定位

- **类型**: 系统级芯片（SoC - System on Chip）
- **架构**: ARM 64位（AArch64）
- **目标**: 边缘 AI 计算、机器人控制、多媒体处理
- **制程**: 8nm 工艺
- **核心**: 8核 CPU（4大4小）+ NPU（神经网络处理器）

### 1.2 核心特性

| 特性 | 规格 | 说明 |
|------|------|------|
| **CPU** | 8核（4×Cortex-A76 + 4×Cortex-A55） | 大核 2.4GHz，小核 1.8GHz |
| **NPU** | 三核架构，6 TOPS 算力 | 支持 INT8/FP16/FP32 精度 |
| **GPU** | Mali-G610 MP4 | 支持 OpenGL ES、OpenCL、Vulkan |
| **内存** | LPDDR4/4X/5，最高 32GB | 带宽高达 68GB/s |
| **存储** | eMMC 5.1 / SD 3.0 / NVMe | 多种启动介质 |
| **接口** | USB 3.1 / UART / GPIO / MIPI CSI | 丰富的外设接口 |

### 1.3 与比赛赛题的关系

RK3588 是本次比赛的**核心硬件平台**。赛题要求将网球拾取机器人系统迁移到 StarryOS，并在 RK3588 上运行。

## 二、核心概念详解

### 2.1 什么是 SoC（系统级芯片）？

**传统电脑 vs SoC 对比**：

| 组件 | 传统台式电脑 | RK3588 SoC |
|------|-------------|------------|
| CPU | 独立芯片（Intel/AMD） | 集成在 SoC 内部（ARM Cortex） |
| GPU | 独立显卡（NVIDIA/AMD） | 集成在 SoC 内部（Mali-G610） |
| 内存 | 独立内存条 | 通过内存控制器连接（LPDDR） |
| NPU | 无（需额外购买） | 集成在 SoC 内部 |
| 体积 | 大（机箱+主板） | 小（邮票大小） |
| 功耗 | 高（200-500W） | 低（2-12W） |

**SoC 的优势**：体积小、功耗低、成本低、性能优化（各组件间通信更快）

### 2.2 什么是 SD 卡？

**SD 卡**是一种闪存存储卡，在 RK3588 开发板上主要用于：

| 用途 | 说明 | 类比 |
|------|------|------|
| **系统启动** | 存放操作系统镜像 | 电脑的 C 盘 |
| **数据存储** | 存放应用程序、模型文件 | 电脑的 D 盘 |
| **系统调试** | 方便更换系统版本 | U 盘安装系统 |

**SD 卡的分区结构**：
```
SD 卡（32GB）
├── 分区 1: boot（256MB）- u-boot.bin、boot.img、设备树
└── 分区 2: rootfs（剩余）- 系统文件、应用程序
```

### 2.3 什么是 eMMC？

**eMMC**是焊接在主板上的闪存存储。

**SD 卡 vs eMMC 对比**：

| 特性 | SD 卡 | eMMC |
|------|-------|------|
| **物理形态** | 可插拔 | 焊接在主板 |
| **速度** | 10-100 MB/s | 100-400 MB/s |
| **稳定性** | 容易松动 | 稳定可靠 |
| **适用场景** | 开发调试 | 产品量产 |

**开发阶段用 SD 卡**（灵活），**产品阶段用 eMMC**（稳定）。

### 2.4 什么是 U-Boot？

**U-Boot**是操作系统的"快递员"，负责把系统从存储介质送到内存并启动。

**两阶段启动**：

| 阶段 | 名称 | 大小 | 功能 |
|------|------|------|------|
| **第一阶段** | SPL | ~50KB | 初始化内存、加载完整 U-Boot |
| **第二阶段** | U-Boot | ~500KB | 加载内核、设备树 |

**与 StarryOS 的关系**：
- U-Boot 负责加载 StarryOS 内核到内存
- 传递设备树（DTB）给内核
- 优化方向：可实现 StarryOS 专用轻量级 BootLoader 减少启动时间

### 2.5 什么是设备树（Device Tree）？

**设备树**是描述硬件资源的数据结构，告诉操作系统板子上有哪些设备。

**为什么需要设备树**：同样的 StarryOS，通过不同设备树文件适配不同板子，无需修改内核代码。

**编译流程**：`.dts 文件（源码）` → `.dtb 文件（二进制）` → `U-Boot 加载到内存` → `内核读取并初始化硬件`

## 三、RK3588 硬件架构

### 3.1 CPU 架构

RK3588 采用 **big.LITTLE** 架构：4 个大核（Cortex-A76, 2.4GHz）+ 4 个小核（Cortex-A55, 1.8GHz）。

**大核 vs 小核**：

| 特性 | Cortex-A76（大核） | Cortex-A55（小核） |
|------|-------------------|-------------------|
| **性能** | 高（计算密集型） | 低（轻量任务） |
| **功耗** | 高 | 低 |
| **用途** | NPU 推理、视觉处理 | 后台服务、I/O 控制 |

**与项目的结合 - CPU 分配策略**：

| 任务 | 推荐核心 | 原因 |
|------|----------|------|
| YOLO 目标检测 | A76 大核 | 计算密集，需要高性能 |
| 逆运动学计算 | A76 大核 | 实时性要求高 |
| 串口通信（电机控制） | A55 小核 | I/O 密集，计算量小 |
| 日志记录 | A55 小核 | 后台任务 |

**优化方向（阶段 3）**：使用 CPU 亲和性绑定任务到特定核心，大核专注实时控制，小核处理后台任务。

### 3.2 NPU 架构

RK3588 内置**三核 NPU**，算力高达 **6 TOPS**。

**NPU 支持的精度**：

| 精度 | 算力 | 适用场景 |
|------|------|----------|
| **INT8** | 6 TOPS | 推理部署（推荐） |
| **FP16** | 3 TFLOPS | 高精度推理 |
| **FP32** | 1.5 TFLOPS | 训练/调试 |

**NPU 推理流程**：`PyTorch 模型(.pt)` → `ONNX 导出(.onnx)` → `RKNN-Toolkit2 转换(.rknn)` → `部署到 RK3588 NPU 推理`

**与项目的结合 - 性能对比**：

| 推理方式 | 帧率（FPS） | 延迟 | 功耗 |
|----------|-------------|------|------|
| CPU（ONNX Runtime） | ~10 FPS | ~100ms | 高 |
| NPU（RKNN INT8） | ~50 FPS | ~20ms | 低 |
| NPU（RKNN FP16） | ~30 FPS | ~33ms | 中 |

**优化方向**：使用 INT8 量化降低延迟，NPU 与 CPU 并行处理。

### 3.3 外设接口

RK3588 提供丰富的外设接口：USB 3.0×2、USB 2.0×3、UART×5、I2C×8、GPIO×124、MIPI CSI×4 等。

**与项目的接口映射**：

| 项目组件 | 接口类型 | 说明 |
|----------|----------|------|
| USB 摄像头 | USB 3.0 | 视觉输入 |
| 机械臂控制器 | USB 2.0 | ACT 模式控制 |
| 电机驱动板 | UART (UART2) | 串口通信 |
| NPU | 内部总线 | RKNN 推理 |
| SD 卡 | SDMMC | 系统启动 |

## 四、启动流程

### 4.1 完整启动流程

```
电源上电 → Boot ROM → U-Boot SPL（初始化内存） → U-Boot（加载内核、设备树） → StarryOS 内核 → 根文件系统 → 应用程序
```

### 4.2 各阶段时间分析（Linux 基线）

| 阶段 | 时间（Linux） | StarryOS 目标 | 优化空间 |
|------|---------------|---------------|----------|
| U-Boot SPL | ~0.5s | ~0.3s | 裁剪初始化项 |
| U-Boot 完整 | ~1.5s | ~1.0s | 减少设备扫描 |
| 内核加载 | ~2.0s | ~1.0s | 内核裁剪 |
| 文件系统挂载 | ~1.0s | ~0.5s | 精简服务 |
| 应用启动 | ~1.0s | ~0.5s | 优化依赖 |
| **总计** | **~6.1s** | **~3.4s** | **44% 提升** |

### 4.3 与项目的结合 - 阶段 1 任务

需要完成的工作：
1. 编译 U-Boot（针对 RK3588）
2. 编译 StarryOS 内核（AArch64 架构）
3. 制作启动 SD 卡（烧录 U-Boot、内核、根文件系统）

**调试技巧**：通过 UART 串口查看启动日志，U-Boot 阶段按空格键进入命令行，使用 `dmesg` 查看内核启动信息。

## 六、NPU 模型部署

### 6.1 模型转换流程

从 PyTorch 到 RKNN 的完整流程：

1. **导出 ONNX 模型**：使用 `torch.onnx.export()`
2. **转换为 RKNN 模型**：使用 RKNN-Toolkit2 的 `rknn.load_onnx()` 和 `rknn.build()`
3. **在 RK3588 上部署**：使用 RKNN-Lite2 的 `rknn.load_rknn()` 和 `rknn.inference()`

### 6.2 INT8 量化

**原理**：将 FP32（32位浮点）转换为 INT8（8位整数），减少计算量和内存占用。

**效果对比**：

| 精度 | 模型大小 | 推理速度 | 精度损失 |
|------|----------|----------|----------|
| FP32 | 100 MB | 100 ms | 无 |
| FP16 | 50 MB | 50 ms | 极小 |
| INT8 | 25 MB | 20 ms | <1% |

### 6.3 与项目的结合 - YOLO 模型优化路径

| 优化阶段 | 方法 | 预期帧率 | 实现难度 |
|----------|------|----------|----------|
| 基线 | CPU ONNX Runtime | 10 FPS | 低 |
| 阶段 1 | NPU INT8 量化 | 40-50 FPS | 中 |
| 阶段 3 | 模型轻量化（YOLO-Nano） | 60+ FPS | 高 |
| 阶段 3 | NPU + CPU 并行 | 70+ FPS | 高 |

**关键问题**：量化校准数据集需要收集网球场景的真实图像，后处理（NMS）仍在 CPU 上运行。

## 七、外设驱动开发

### 7.1 项目所需驱动

| 优先级 | 驱动 | 依赖关系 | 开发难度 | 预计时间 |
|--------|------|----------|----------|----------|
| 1 | UART 串口 | 无 | 中 | 3-5 天 |
| 2 | USB 摄像头 | USB 框架 | 中 | 5-7 天 |
| 3 | GPIO | 无 | 低 | 1-2 天 |
| 4 | I2C（传感器） | I2C 框架 | 高 | 7-10 天 |

### 7.2 驱动开发要点

**USB 摄像头驱动**：使用 V4L2 框架，通过 `/dev/video0` 访问，调用 `ioctl()` 控制捕获。

**UART 串口驱动**：通过 `/dev/ttyS2` 访问，波特率 115200，用于控制机械臂电机。

**GPIO 驱动**：使用 `gpiod` 库，控制 LED 指示灯、读取按钮状态。

### 7.3 与项目的结合 - StarryOS 驱动开发

- StarryOS 使用 Rust 语言，需要编写 Rust 驱动
- 可以参考 Linux 驱动的架构设计
- 需要实现 Linux 兼容的接口（如 VFS）

## 九、调试与故障排查

### 9.1 串口调试

**连接方式**：RK3588 TX → 串口模块 RX，RK3588 RX → 串口模块 TX，GND → GND

**常见错误排查**：

| 错误现象 | 可能原因 | 解决方法 |
|----------|----------|----------|
| 无任何输出 | 电源未接通/串口未连接 | 检查硬件连接 |
| "Booting from SD" 卡住 | SD 卡损坏/镜像错误 | 重新烧录 SD 卡 |
| "Kernel panic" | 内核配置错误/设备树不匹配 | 检查内核配置 |
| "NPU init failed" | NPU 驱动未加载 | 检查设备树和驱动 |

### 9.2 常用调试命令

```bash
uname -a                    # 内核版本
cat /proc/cpuinfo           # CPU 信息
cat /proc/meminfo           # 内存信息
lsusb                       # 查看 USB 设备
dmesg | grep tty            # 查看串口设备
top                         # 进程监控
```

### 9.3 与项目的结合 - 调试技巧

| 技巧 | 说明 | 适用场景 |
|------|------|----------|
| 串口日志 | 查看完整的启动过程 | 启动失败、内核崩溃 |
| dmesg | 查看内核日志 | 驱动加载失败、硬件错误 |
| perf | 性能分析 | 性能优化、瓶颈定位 |
| 最小系统 | 只保留必要功能 | 问题隔离 |
